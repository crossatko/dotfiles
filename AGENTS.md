# AGENTS.md — dotfiles handbook for AI agents

Read this first. It describes the machines, the repo, the conventions and how the config works, so you can continue without re-deriving it. It is a state document, not a changelog (history lives in `git log`). It deliberately contains no concrete config values (sizes, gaps, opacities, timeouts, keybinds, colours): the config files are the source of truth, each section names the file. The user's own apps document themselves in their repos (see "Own apps").

## Working rules (mandatory)

### 0. Public repo: never write real setup details

This repo is **public on GitHub**. Never write anything identifying the user's private setup into it: in code, comments, docs, tests, notes, commit messages or screenshots. That means:
- no tailnet / Tailscale names (`*.ts.net`, MagicDNS short names); <!-- privacy-ok -->
- no real URLs of private services or IP addresses (LAN/RFC1918, Tailscale `100.64.0.0/10`), MAC addresses, device serials (monitor descriptions with serials, Bluetooth addresses); <!-- privacy-ok -->
- no usernames, accounts or emails, tokens or keys, personal channel / server / library / calendar names.

Machine names (Battlestation, Workstation, the Mac) and hardware class are fine: the code uses them. Use placeholders for the rest: `jellyfin.example`, `192.0.2.10`, `user@example.com`, `<token>`. Real values live outside the repo (`~/.config/<tool>/...`, `~/.local/state/...`) or in git-ignored files (`config/hypr/.secrets`). Agents may tell the user real values in chat, never write them to repo files.
Enforced by `.githooks/pre-commit` (`git config core.hooksPath .githooks`, set by `install.sh`): it blocks staged lines matching generic patterns plus a private deny-list at `~/.config/dotfiles-private/denylist` (outside the repo). A line containing `privacy-ok` is skipped; `--no-verify` only on the user's explicit decision.

### 1. Global rules

Subagent delegation, change documentation (notes = how it works + where it is + short caveats, never copied config values; each app documents itself) and the no-attribution rule live in the global `CLAUDE.md` (this repo's `CLAUDE.md` is linked to `~/.claude*`). They apply here too.

### 2. Safety rules learned the hard way (repo-specific)

- **Kill Quickshell only by exact PID.** The user's shell is the bare `/usr/bin/quickshell` process. `pgrep -x quickshell` also matches other instances (the Twitch app, probes); killing by name or relaunching blindly creates duplicates.
- **Don't edit a popup's QML file while that popup is open.** Hot reload crashed Qt's Repeater (segfault) twice. Test in an isolated instance (`quickshell -n -p <dir>`) or with the popup closed.
- Hot reload only works for files already loaded. A new QML type needs a `qmldir` entry AND a full quickshell restart: the running shell does not re-read `qmldir` on hot reload ("X is not a type"; settings pages load lazily, so it only shows when the page opens). Restart: kill the exact quickshell PID, then `hyprctl eval 'hl.exec_cmd("env QSG_USE_SIMPLE_ANIMATION_DRIVER=1 quickshell")'` (`hyprctl dispatch exec` silently does nothing with the Lua config). Changed `.frag`/`.qsb` shaders are not hot-reloaded either. A failed reload keeps the old generation running.
- Don't touch the screen-sharing portal routing (`config/xdg-desktop-portal`). ScreenCast/RemoteDesktop/Screenshot must stay on the Hyprland portal.
- **Secrets:** `config/hypr/.secrets` is git-ignored; the tracked `config/hypr/.secrets.example` lists the keys (OpenRouter, Home Assistant URL/token/webhooks). Never print, log or commit values. WiVRn pairing data (`config/wivrn/`) is also not tracked.
- **Licensed fonts stay out of the repo.** The Font Awesome Pro desktop set is installed in `~/.local/share/fonts/FontAwesomePro/` only (Brands comes from the system package).
- Screenshot tips: `grim -g "x,y WxH"`; Hyprland dims unfocused windows (focus first when sampling colours); popups open on the *focused* monitor. The user switches workspaces under you: capture only after checking the active workspace and that no foreign window overlaps.
- Never run `theme.py` from a scratch copy with the real `HOME` (it rewrites links in `~/.config` and `~/.local/share/themes`); set `HOME` in the same command.

## The machines

- Plain Arch Linux, **Hyprland with the native Lua config** (`hl.*`, not a plugin), Quickshell (QML) for bar/launcher/notifications, hyprpaper, hyprlock.
- **Battlestation** (primary desktop): two 2560x1440 monitors (a 360 Hz OLED main one and a 60 Hz one), RX 9070 XT, plus a living-room 4K TV output used for Steam Big Picture / gamescope sessions (TV scripts below). Runs the user's **Hyprland fork** (glass compositing, see "Own apps"). Corne keyboard with VIA.
- **Workstation** (work machine): stock Arch `hyprland` (no glass), ultrawide 3440x1440 plus a portrait second monitor, RX 5700 (no AV1 hardware decode). Corne keyboard with Vial.
- **Mac** (secondary, shared laptop): see the macOS section.
- Per-host differences live in `config/hypr/hyprland/host.lua` (`$HOSTNAME` is read first, so tests override the host with it; matches are on hostname substrings; `is_vm` is any hostname ending in `-vm`/`vm` (e.g. `xyz-vm`), `is_archlinux` is the stock hostname) and `config/hypr/hyprland/monitors.lua` (outputs, connector/serial map; used by `rules.lua`, `workspaces.lua`, `settings.lua`, `env.lua`, `autostart.lua` and the scripts via `is_battlestation` / `is_workstation`).
- Only `~/dotfiles/config` is live (symlinked into `~/.config`; `config/shell/` holds the shell dotfiles linked into `~` by `install.sh`). `install.sh` is the Arch bootstrap (see "Repository map"); `system/etc/` holds root-owned files that need sudo (the agent has no sudo; see `system/README.md`).
- UI font: Paper Mono. Icon font: **Font Awesome Pro Sharp (Regular)** plus Font Awesome Brands (system package) for brand logos.
- Hyprland dispatch: `hyprctl dispatch "hl.dsp.focus({workspace=N})"`; window focus `hl.dsp.focus({window="address:0x..."})`; monitor focus `hl.dsp.focus({ monitor = "<connector>" })`. `hyprctl keyword` is refused with the Lua config. Lua globals can be called with an IIFE: `hyprctl dispatch '(function() if pip_bar_changed then pip_bar_changed() end return hl.dsp.exec_cmd("true") end)()'`. Lua monitor objects expose name/serial/description but **not** model. Hyprland Lua objects (monitors, workspaces, windows) are userdata: test with nil checks, never `type(x) == "table"`. `hl.dsp.window.pin({action=true})` TOGGLES. `Hyprland --verify-config` dumps core, so there is no CLI config check; use `hyprctl configerrors` after a reload.
- `xdg-mime default org.gnome.Nautilus.desktop inode/directory` is set in the untracked `~/.config/mimeapps.list` (otherwise folders open in a terminal); a new machine needs it.

## How to test (all features, described once)

- **Isolated shell:** copy `config/quickshell` to a short dir (or start from `git archive HEAD config/quickshell` and copy changed files over it to rehearse hot reload), make a test `HOME` (`.config/theme` and `.local/share/fonts` symlinked, copies of `.local/state/quickshell/*.json`) plus `XDG_{CONFIG,STATE,CACHE,DATA}_HOME` inside it, a short `XDG_RUNTIME_DIR` with `hypr`/`wayland-1` symlinks to the live one, and run `dbus-run-session --config-file=<conf without <servicedir>>  quickshell -n -p <dir>`. Drive it with `quickshell ipc --pid <pid> call ...`; temporary test-only `IpcHandler`s go in the copy only. Env hooks for state files, binaries and fixtures are `QS_*` (e.g. `QS_APPEARANCE_FILE`, `QS_ANIM_FILE`, `QS_WALLPAPERS_FILE`, `QS_HYPRCTL` stub binary, `QS_HA_*`, `QS_AI_*`, `QS_TAILSCALE`/`QS_MULLVAD`, `QS_AIRPODS_*`, `QS_LAUNCHER_NET_FIXTURE`, `QS_BTNOTIF_FIXTURE`) plus `SCREENREC_*` and `SHOT_*`; `grep -rn 'Quickshell.env\|QS_' config/quickshell` lists them. A scratch launcher/modal must not take focus (`ModalMenu` grabs exclusive keyboard focus): set `keyboardFocus: None` and an empty mask in the copy. Kill by exact PID, then orphaned poller shells (ppid 1) of the test HOME.
- **Nested compositor** (anything about glass, scale, layers, window rules, wallpapers, GTK/Qt apps): start `Hyprland -c <config copy>` with its own short `XDG_RUNTIME_DIR` (socket paths must be short; `WAYLAND_DISPLAY` absolute if needed), hidden via `hl.dsp.exec_cmd(cmd, {workspace="special:x silent", no_initial_focus=true})` or floated on a monitor, add outputs with `hyprctl output create headless TEST` + `hl.monitor({output='TEST', mode='WxH@60', scale=s})` + `hyprctl reload`. Export the nested `XDG_RUNTIME_DIR` / `HYPRLAND_INSTANCE_SIGNATURE` / `WAYLAND_DISPLAY` (never `ls -t` for the signature; the user may run other nested instances), capture with `grim -o TEST` on the nested socket, and put a solid/checkerboard backdrop window or layer behind translucent things. Headless outputs only render while the nested window is visible. Use `/usr/bin/Hyprland` for stock behaviour, `/usr/local/bin/Hyprland` for the fork. `bars.json` in the test HOME must enable `TEST` (headless outputs have no model, key = name).
- **Never inject synthetic input into the live session.** Real clicks/drags/keys are "not verified" unless the user does them; the nested instance may be driven with `hl.dsp.send_shortcut`, `hl.dsp.cursor.move` or a virtual-pointer client that refuses any socket but the nested one.
- **Unit-level:** `python3 -I config/theme/selftest.py` (extractor, must pass for any wallpaper), `python3 -I -m unittest discover -s config/url-router/tests`, `... -s config/launcher/jellyfin/tests`, `... -s config/quickshell/bin/tests` (webapp helper), `node --test config/quickshell/launcher/js/tests/*.test.js` (launcher JS), `bash config/quickshell/launcher/bin/tests/code-open.test.sh`, `python3 -I config/quickshell/launcher/bin/tests/vm-ctl.test.py`, `luac5.5 -p` on Lua files, `qmllint` (the one on PATH is Qt5 and checks nothing useful: use `cd config/quickshell && /usr/lib/qt6/bin/qmllint -I /usr/lib/qt6/qml --json - $(find . -name '*.qml')`. Use `--json`: Qt 6.12's text output silently drops every located warning of a file that contains a `for (... of ...)` loop (most files here), exit code stays 0; to tell new warnings from old, lint a `git archive HEAD config/quickshell` export the same way and diff by file/id/message/source line. The JSON has baseline warnings (the `Type X not declared as singleton in qmldir` false positives, qmltypes gaps); remaining gaps are suppressed with a trailing `// qmllint disable <category>` on that line; do not disable `import` globally, it hides missing modules), `qmltestrunner` (offscreen) for pure QML logic (test files kept outside the repo).
- **Measuring bar/chip alignment:** temporary `console.log` of `mapToItem(null,0,0)` + size, `grim -g` crops, per-chip background interpolation; judge on fractional-edge margins, not bbox.

## Theme system (`config/theme`)

Details (usage table, extractor, what reloads how, Qt/GTK/Brave notes): `config/theme/README.md`. What matters when editing:

- **One place to edit:** `theme.toml` (+ `templates/`). Never hard-code colours in an app config.
- **The theme is per machine; a wallpaper switch changes no tracked file.** Tracked: `theme.toml` (settings, `wallpaper` = the default) and `default/` (a generated neutral wallpaper + the outputs rendered from it, regenerate with `theme.py default`, home-independent `~/` paths). Git-ignored: `theme.local.toml` (this machine's `wallpaper`, written by `apply` / the picker; optional local `[settings]`, `[overrides]`, `[vars]` `tv_wallpaper` / `static_blocks`, merged over `theme.toml`) and `out/` (this machine's render, what every app reads).
- **Seeding:** `bin/theme-seed` (POSIX sh; used by `install.sh`, `theme.py`, the git hooks) fills a missing `out/` from `default/` and writes `out/.default`, but **only on a machine without `theme.local.toml`** (fresh clone, the Mac). A machine with a selection whose `out/` is missing or incomplete gets `theme.py render` from the hooks instead (`THEME_SEED_FORCE=1` seeds anyway). `out/` can vanish when a rebase / merge replays the untracking commit, so the hooks (`post-merge`, `post-rewrite`, `post-checkout` -> `theme-render`) repair it; `THEME_RENDER_SKIP=1` skips the render. `steam-tv-dim.lua` / `steam-streaming.lua` re-apply `palette.lua`'s `wallpaper` to hyprpaper on TV resyncs. Fatal consumers have fallbacks: Hyprland `theme.lua` and nvim `pcall(dofile, out/palette.lua)` then `default/palette.lua`, ghostty uses `config-file = ?...`. herdr has no include: `deploy()` writes `~/.config/herdr/config.toml` as a generated file, so a herdr settings edit needs `theme.py render`. A missing `out/` file: kitty ignores the include, ghostty (`?`) is silent, zellij's `wall.kdl` (tracked symlink into `out/`) dangles, hyprlock/hyprtoolkit/hyprpaper need the seeded file.
- `theme.py apply <img>` extracts a palette from the wallpaper (own extractor), renders templates to `out/` and live-reloads the apps (kitty, ghostty, alacritty, nvim, zellij, herdr, hyprland/hyprlock/hyprpaper, quickshell, GTK CSS, KDE/qt6ct palette, icons, Brave, Thunderbird). Picker = Settings > Wallpaper & theme (`qs ipc call picker toggle`). Wallpaper and video folders: `wallpaper_dirs` / `video_dirs` in `theme.toml`.
- Layout defaults live in `theme.toml [settings]` and go to `out/palette.json`, driving **Quickshell only**; `out/palette.lua` carries just `wallpaper`, `rounding` and colours, and Hyprland's own values stay hand-written in `hypr/hyprland/` (`theme.lua`, `settings.lua`; keep the two in sync when changing a default). User overrides live in `appearance.json` (see Appearance).
- **Per-host output:** GTK3/GTK4 CSS, `kvantum.kvconfig` and `brave-glass.css` are rendered into git-ignored `out/host/` because the fill alpha depends on the compositor (fork vs stock). After pulling on a new host run `~/.config/theme/theme.py render` once (relinks GTK CSS; until then GTK apps use stock Adwaita). On macOS the engine never runs (`theme.py` exits 0 on darwin), only the seeding.
- **Migrating from the old tracked `out/*` (other Linux machines, one-off):** `theme-render` runs `theme.py adopt-legacy` (reads a copy of the old `out/`, `theme.toml` and herdr config from `~/.local/state/theme/legacy/`, else the `ORIG_HEAD` blobs): the previous wallpaper goes into `theme.local.toml`, local `[settings]`/`[overrides]` edits become local overrides, then it renders. Git refuses to pull while the old tracked `out/*` has local edits; copy them to that folder first, then `git checkout -- config/theme config/herdr`.
- Qt: `QT_QPA_PLATFORMTHEME=kde` (`hypr/hyprland/env.lua`), Kvantum theme `Wall` (`theme.toml qt_style = "kvantum"`; falls back to Fusion with a message if Kvantum is missing, install `kvantum` + `kvantum-qt5`). Brave/Chromium dialogs use the GTK theme via `GTK_THEME`; portal FileChooser = `xdg-desktop-portal-gnome`.
- **Light / dark mode:** `theme.py mode [get|dark|light|toggle]`, UI = Settings > Wallpaper & theme > Color mode. The mode is per machine in `~/.local/state/theme/mode` (default dark); `hypr/hyprland/autostart.lua` sets the freedesktop `color-scheme` from it at login, `theme.py` keeps it on every apply; theme writes are serialised by `~/.local/state/theme/apply.lock`. Glass settings are per mode (`theme.toml` `[settings]` / `[settings_light]`, `glass.json`; `managed.lua`, `GlassTuneCtl.qml`). Details and limits: `config/theme/README.md` (Light / dark mode). Check after changes: `python3 -I config/theme/selftest.py`, render dark before / after and diff. Testing the UI nested needs the real `hyprctl` on PATH (a shim makes `Theme.glass` false, so glass-only fills and the Glass page do not show) and a light render's `palette.json` + `palette.lua` in the test HOME's `~/.config/theme/out`; never `pkill -f` with a pattern that matches your own command line.
- Known limits: GTK4/libadwaita cannot restyle open windows; Brave only picks the theme up while closed (the `~/.local/bin/brave` shim, `config/theme/bin/brave`, applies it); `theme.toml` knobs: `thunderbird`, `thunderbird_radius`, `brave_mode`, `gtk_glass*`, `qt_symbolic_icons`.
- `out/hyprpaper.conf` is generated per machine: the tracked template has only the catch-all block, this machine's per-monitor blocks (monitor descriptions with serials) live in `[vars] static_blocks` of the git-ignored `theme.local.toml`; `monitor_blocks` from `wallpapers.json` come last.
- Testing the theme engine without touching the session: temp clone + temp `HOME` with `~/.config/theme` linked to it, `THEME_OUT_DIR` for another `out/`, and shims on `PATH` for `pkill`, `hyprctl`, `gsettings`, `kwriteconfig6`, `herdr`, `hyprpaper` (`apply` reloads apps by name: never run it with the real `PATH`/`HOME` while testing); nested Hyprland for hyprpaper/hyprlock screenshots (a minimal config that requires `hyprland.theme`; the real `autostart.lua` would `pkill hyprpaper`).

### Toolkit glass (GTK4, GTK3, Qt/Kvantum, Brave, Firefox, Thunderbird)

- **Principle:** the compositor already applies tint / darkening / saturation / refraction behind any translucent window with the shell cards' values, so app CSS paints only the card fill (`Theme.cardFill` on solid_glass; `bar_opacity` on plain blur) plus per-part offsets (`theme.toml gtk_glass_*`, `gtk_glass` false = opaque). Repeating tint/darkening in CSS would apply it twice. Glass slider changes reach running GTK apps live; CSS changes (palette, blur variant) need `theme.py apply` and an app restart. `theme.py hypr_solid_glass()` and `Theme.qml` use the same test: keep in sync.
- **GTK4/libadwaita:** `~/.config/gtk-4.0/gtk.css` -> `out/host/gtk4.css` (template `templates/gtk4.css`, link set in `deploy()`), overrides libadwaita named colours with alpha. **Blur needs `backdrop-filter`:** newer GTK4 creates an empty `ext-background-effect-v1` blur region and Hyprland treats that as "no blur", so a `window { backdrop-filter: blur(...) }` rule and popover rules are required. Do not also set `--*-bg-color` variables at user priority (ghostty sets `:root --window-bg-color` itself). User CSS outranks theme CSS regardless of specificity, so every state that changes a fill must be listed. `nautilus --new-window` attaches to a running user instance: test under `dbus-run-session`.
- **GTK3:** `~/.config/gtk-3.0/gtk.css` -> `out/host/gtk3.css`, scoped to `window.csd` (Gecko reads system colours from unrealised contexts without `.csd`, so Firefox/Thunderbird are untouched); menus stay opaque; windows without a header bar stay opaque. GTK3 inlines Adwaita colours, so explicit selectors, not `@define-color`.
- **Qt:** a palette alpha alone stays opaque; Kvantum `translucent_windows` (via `write_kvantum_theme()`: recoloured KvFlat + `out/host/kvantum.kvconfig`) sets `WA_TranslucentBackground`; video apps and quickshell are `opaque=`. `~/.config/Kvantum/kvantum.kvconfig` selects the theme. Metrics copy libadwaita's measured sizes (see `kvantum_svg.py`, `templates/kvantum.kvconfig`, `templates/gtk3.css`). Qt icons: `gen_qt_icons()` builds the Qt icon theme (Adwaita symbolic + fallbacks). Kvantum quirks that cost time: push buttons add extra px over frame+text, default button label colour cannot be set, item-view margins are capped, unfocused windows request `itemview-*-inactive`. Limits: icon-only QPushButtons stay oversized, no Qt switch widget, Qt5 unchecked.
- **Brave (GTK mode, `brave_mode = "gtk"`):** the tab strip uses the GTK `headerbar`/`.titlebar` background including alpha (must be set for `:backdrop` too, else the unfocused window is opaque); the toolbar/omnibox row stays opaque in Chromium. Requires `browser.custom_chrome_frame = true`; `apply_brave()` (run by the shim while Brave is closed) writes it and `extensions.theme.system_theme = 1`. The shim exports a glass GTK theme (`Wall-Glass` = Wall + `brave-glass.css`). The omnibox focus ring and the toolbar's top corner triangles come from Chromium's seed-colour pipeline, not GTK (`brave_gtk_seed` optional). `brave_mode = "seed"` restores the old seed-colour theme.
- **Firefox:** `config/firefox/userChrome.css` + `user.js` linked by `install.sh` into the install-default profile; translucent header via Firefox's own toolbar variables, content forced opaque; `--window-radius` there is a hard-coded copy of the Appearance radius (update by hand). Restart needed; selectors may break on updates.

### Wallpapers (per monitor, videos, links)

- **State:** `${XDG_STATE_HOME:-~/.local/state}/theme/wallpapers.json` (host-local, written only by `theme.py`; `THEME_WALLPAPERS_FILE` / `QS_WALLPAPERS_FILE` override; the schema is in `theme.py`). Session memory via the `memory` page hook. Test hooks: `qs ipc call wallpaperpage tab images|videos`, `... monitor <key>`.
- **Monitor links:** linked monitors always change together (wallpaper apply/mode/timing/follow go to the whole group; "Make primary" stays per monitor). Bars: links live in `bars.json` under the reserved key `"_links"`; linked monitors share on/off, edge and layout (`BarConfig.set` / `BarWidgets.store` write every key of the group; the last-bar rule is about the group). UI: `MonitorCardRow.qml` + `MonitorLinkButton.qml`; round cut-outs around link buttons via `NotchMask.qml` + `shaders/notchmask.frag(.qsb)`. `NotchMask` is a qmldir type: live restart needed.
- **Video wallpapers** (mpvpaper + libmpv): one `mpvpaper -l bottom -o "<opts>" <connector> <file>` per output (hyprpaper stays on `background`, so the video is above the still and below windows), pid files + logs in `$XDG_RUNTIME_DIR/theme-video/`, stop = SIGTERM/SIGKILL only if `/proc/<pid>/comm` is `mpvpaper`, flock serialises syncs. `scripts/start-hyprpaper.sh` runs `theme.py video start` after hyprpaper; `autostart.lua` re-syncs on `monitor.added/removed`. `MPV_OPTS` (in `theme.py`) carry `load-scripts=no` so `mpv-mpris` does not turn wallpapers into MPRIS players (explicit `scripts=winddown.lua` still loads). No `-p` auto-pause (unreliable on Hyprland). Players keep decoding behind windows; looping high-fps 4K sources are the worst case.
  - **Once vs loop:** once = plays, holds the last frame (the login animation); stills (`video_still()`, ffmpeg, cached under `$XDG_CACHE_HOME/theme/video`) feed the palette and the hyprpaper image under the player. The hold point skips a black tail (`video_hold()`); mpv's `end=` is exclusive, so the still is the frame BEFORE the stop time. Timed play-once: `play` seconds then a raised-cosine wind-down over `wind` seconds (`WIND_AVG` shared by `theme.py`, `mpv/winddown.lua` and QML), no `play` = full length. The runtime ramp steps through source frames (choppy), so with Optimize on a per-monitor **baked file** is built (below). `display-fps-override` must equal the real refresh or playback speed scales wrongly (`winddown-fps`).
  - **Optimize for monitor (default on):** per (video, monitor) HEVC copy (H.264 fallback via `out_codec()`; `hevc_vaapi` / libx265; encoders and hardware decode are probed per machine and cached under `$XDG_RUNTIME_DIR/theme-video/probe-*`; `THEME_FORCE_NO_HWDEC`, `THEME_OUT_CODEC`, `THEME_FORCE_ENCODER` simulate other machines) in `$XDG_CACHE_HOME/theme/video/opt/` (LRU-capped), scaled to the monitor's pixels, fps chosen to divide the refresh. `hevc_vaapi` + `hvc1` needs `-bsf:v extract_extradata` (else undecodable). Apply plays the original at once, the copy swaps in at an invisible point; if the source has no hardware decode here (AV1 on the Workstation GPU) the still stays until the copy is ready (`video_wait_for_copy`). Stills/palette always come from the original. Speed modes (Background / Balanced / Fast) re-prioritise the runner live (SIGUSR1); cancelling kills only the stale job's ffmpeg/RIFE process groups.
  - **Baked wind-down and replay bursts:** a baked file = first play + a chain of short **bursts** (ease-in then cosine wind-down; sidecar `<bake>.json`), RIFE (`rife-ncnn-vulkan` from the AUR; fallback ffmpeg `minterpolate`) synthesising the in-between frames. Every workspace switch (except special workspaces) plays the next burst and holds (`scripts/video-replay.lua` -> `mpv/replay.py <connector>` -> mpv IPC `winddown-restart`; ignored while a burst plays); station survives a player restart (`<runtime>/theme-video/<conn>.station`); the launcher also replays when the focused workspace is empty. Loops wrap around (capped by `burst_kmax`), non-loop clips restart from burst 0. RIFE runs as a few long-lived directory-mode processes (workers sized by free VRAM, OOM halves them). Bakes ignore load; `THEME_BAKE=0` disables. Colour: the PNG round trip must use the source's matrix/tags (`RGB_UP`, `bake_rgb_down`) or luma shifts; `BAKE_VERSION` / `OPT_VERSION` are in the cache keys. Do not compare `psnr` across files of different frame counts.
  - **Caveats:** baking cost grows with burst count; a failed/pending encode leaves the original running; monitor disconnect can segfault mpvpaper (stale pid file reaped by the next sync); unreadable videos show an "unreadable" cell and `apply` exits 1; changing a monitor's refresh later needs `theme.py video restart`; untagged videos can get a different matrix in the still. Not verified: the Workstation GPU path, nvenc/qsv, real pointer drags on the Settings sliders.
  - Try it live: `python3 ~/.config/theme/theme.py render`, Settings > Wallpaper & theme, `theme.py video status`, `hyprctl layers -j` (mpvpaper must be in layer level 1).

### Shared building blocks (use these, do not hand-roll)

`Icon` (FA glyph Label; bar chips use `BarIcon`), `PanelHeader`, `ListRow` + `RowText` + `RowState` (list cards), `Notice` (confirmation / error / empty / setup steps), `LevelRow` (icon + `Slider` + value), `Meter`, `Segmented`, `SettingRow`, `Btn`, `Toggle` (only on main-section headers; item rows use `RowState`), `ModalMenu` + `KeyBadge` (keybind-opened layer modal, used by `Launcher`), `PopupRegistration` (registers click-away things with `Popups`), `HoverGlow`, `SwipeDismiss`, `Icons.volumeGlyph`. Recipes: new popup = file with `PanelHeader` + sections, name in `PopupHost`'s content switch and width map, chip calls `bar.pop`, qmldir entry; new list row = `ListRow` + `RowText` + `RowState`/`Btn`; click-away non-popup = `PopupRegistration`.
- **HoverGlow:** pointer-following radial light, fill colour = the parent's current fill; pointer tracking is a passive `HoverHandler` re-parented to the item (a child control's hover would otherwise drop `containsMouse`). `glow.hovered` is also what flat hover tints use. Built into ListRow/Tile/Btn/Toggle/Segmented and most cards. Not on Sliders (user decision) or text links.
- **Slider:** the handle's radius is clamped by `Theme.radius`; `wheel: false` on every Slider inside scrolling Settings pages (a wheel over a timing slider once triggered a full theme apply). While pressed it grows into an in-app **glass lens** (`shaders/sliderlens.frag` + committed `.qsb`; rebuild with `/usr/lib/qt6/bin/qsb --qt6 -o sliderlens.frag.qsb sliderlens.frag` in `shaders/`; Qt caches a ShaderEffect shader per URL for the process life, restart after changing it): a `ShaderEffect` fed by a child `ShaderEffectSource` (must be a visual child, a parentless source segfaulted on window hide); optics are a port of the fork's `solidglassfinish.frag` driven by `GlassTuneCtl.values` (fork) or `defaults()` (stock); no lens on the software scene graph or a shader error.
- **Qt/QML gotchas:** files with delegates / nested `Component`s start with `pragma ComponentBehavior: Bound` (before the imports) and every delegate declares `required property` for `modelData` / `index` / roles; `||` is for string / object fallbacks only, use `??` where `0` / `false` is valid; `Process` commands take argv arrays, never user data spliced into `sh -c` (positional args: `sh -c '... "$@"' sh arg...`); pollers bind `running` to visibility (`BarWidgets.shown(id)`, `panelOpen`); no `console.log` of notification content or the HA host; never use endless shell loops in a `Process` (they orphan to systemd on restart): poll with `Timer` + `FileView.reload()` (works on /proc) or one-shot Processes; no inline `component X:` in a file the running shell already loaded without one; hot reload is triggered by watched `.qml` files only (not `qmldir`) and a multi-file write (checkout, stash pop) can reload between files: a stale `qmldir` / new file then gives "X is not a type" until the next edit of any loaded file; a `Binding` whose `target` lacks the property warns even when `when` is false; never bind an item's own `visible` to its `visibleChildren` (latches off); a property named like an id shadows it; `clip: true` clips to the bounding box, not the rounded shape (use a MultiEffect mask for media art when radius > 0); `layer.effect` shader masks are not clipped by hot reload; singletons are not warmed in isolated instances; `Chip`'s hover MouseArea sits at `z: -1` so child MouseAreas get clicks; Binding-loop-prone `x` reading laid-out values goes into a delayed `Binding` (Chip row x); a `Behavior` easing must never be a binding that flips on close (use explicit open/close animations); a QML function named `closed` clashes with the window signal.

### Notifications

`Notifs.qml` is the notification server (history, dedupe `Notifs.repeats`, DND, `qs ipc call notif dnd|clear|replay`). **Toasts and the notification center are ONE stack** (`NotifStack`) in two modes, hosted by `Toasts.qml` (window `qs-toast`, not PopupHost): toast mode shows one `NotifSlot` per active toast (`Notifs.popups`); the clock chip toggles popup `notif` and the stack goes to list mode (history, newest first, toasts already on screen stay where they are, older ones slide in). `NotifCard` is the one glass card (buttons: app actions plus `Copy <code>` and `Open <host>` derived from the body); `NotifHeader.qml` is the bottom row (Clear, scroll hint; the historical name stays because a renamed type needs a shell restart); `NotifEmpty` the empty state. Clear (`NotifStack.clearAll`) flies the visible cards out one by one and closes the rest at once. Dismiss paths: click = default action + `bin/focus-app`; right-click or swipe (`SwipeDismiss`, single path `NotifCard.dismiss()`) dismisses. Stand-in objects from `replay` are not tracked by the server, so `NotifSlot` hands them to `Notifs.releaseLater`. The list scrolls by whole cards (nothing is clipped because `Glass.qml` cannot clip regions). Timing and counts are constants in those files. The notification windows are full screen and never resized, so no stale buffer can be stretched.
- **Notification icons** (`NotifIcon.qml`): real image / explicit path = as is; shell asset (`assets/`) = tinted; standard freedesktop name (`launcher/js/NotifGlyph.js`) = Font Awesome glyph via `Icon`; app-specific = its own icon; unknown = symbolic Adwaita.
- **Click -> web app window:** Chromium sends every notification as `app_name=Brave`, `desktop-entry=brave-browser`; `NotifCard.activate()` passes the `x-kde-origin-name` hint as 4th arg to `bin/focus-app`, which scores a window whose class matches `^(brave|chrome|chromium)-<host>__` highest; no such window -> the main browser. Unverified with a real Brave notification (hint value assumed host or URL). Test: `bash config/quickshell/bin/focus-app brave-browser Brave "" <host>`.

### Bar chip and icon alignment

- Tokens in `Theme.qml`: `chipHeight`, `chipPadX`, `chipGap`, `chipIcon`. `Chip.qml` sizes itself from its content; **never set `implicitWidth` on a chip, never use `BarLabel` with the icon font.** Add a chip: `Chip { BarIcon { text; color } BarLabel { ... } }`.
- `BarIcon` is a fixed-size box with the glyph's *rasterised* ink centred (`InkMeter`: a Canvas that draws the string with the same font and scans alpha; x exact and not snapped, vertical baseline on a whole DEVICE pixel). `InkMeter.dpr` = `QsWindow.window.devicePixelRatio` (fractional; `getImageData` returns raw device pixels). `Chip` centres the row on the visible ink of its first/last item. Don't read child `x`/`width` inside those bindings (binding loop). Tray bitmaps keep their own padding. Not every fractional scale is valid (Hyprland snaps the scale to what the mode allows). No `QT_SCALE_FACTOR*` is set.

### Appearance (radius, gaps, floating bar)

Settings > Appearance changes corner radius, gaps, border and smart gaps (globally and per monitor), in Hyprland AND Quickshell, live.
- **Data:** `${XDG_STATE_HOME:-~/.local/state}/quickshell/appearance.json`; keys are listed in `Appearance.qml` (`keys`; limits and clamping there and in `managed.lua`). Missing key = theme default; `{}`/no file = all defaults; invalid input falls back to defaults. Precedence: Quickshell `appearance.json` > `theme.toml [settings]` > fallbacks; Hyprland `appearance.json` > hand-written config. Monitor key = description as Hyprland reports it (connector as fallback, same rule `Appearance.monitorKey()` / `M.monitor_key()`); identical monitors without serial share a key.
- **Writers/readers:** only `Appearance.qml` writes (debounced, then `hyprctl eval "if layout_apply then layout_apply() end"`; `hyprctl reload config-only` instead when the smart-gaps keys changed; hand edits are picked up by a FileView watch). `theme.py` never touches the file. Hyprland reads it at every config load.
- **`hypr/hyprland/managed.lua`** holds everything Appearance does in Hyprland (never put hand-written settings there): loaded by `pcall(require, "hyprland.managed")` from `hyprland.lua` after the hand-written modules (keep it after them). It applies only the keys that are set (`hl.config` each in `pcall`), remembers a baseline read with `hl.get_config` and restores it on reset, and registers the smart-gaps rules (catch-all set plus one set per connected monitor, flipped with `set_enabled`; hot-plug via `hl.on("monitor.added"|"monitor.removed"|"hyprland.start")`; subscriptions are removed at the next load so a reload does not stack them). Global `layout_apply()` never raises. A Lua error at config load disables the rest of the config, so everything is `pcall`ed and clamped. Hyprland auto-reloads on save, so every file must load alone. The same file also does animations (`anim_apply()`), glass options (`apply_glass`) and `apply_glass_layer_alpha()`.
- **Theme.qml API:** mirrors `radius`, `gap`, `gapIn`, `gapOut`, `borderSize`, `barFloating`, `smartGaps`; bar `barGap`, `barRadius`, `barPad`, `barReserve`; popups `popupGap` and `edgeGap` — **`Theme.edgeGap` is NOT the user's `edgeGap` key (that is `Theme.gapOut`)**; concentric rule `inner(outer, inset)` and named radii `radiusChip`, `radiusItem`, `radiusPage`, `radiusDeep`, `radiusModal`. Pills keep `min(h/2, ...)`. `Btn` takes `outerRadius` / `inset`; buttons not directly in a popup card set both (see the Settings close/page buttons for examples). Definitions: `Theme.qml`.
- **Docked vs floating is per bar** (Settings > Bar > Style, `bars.json` key `floating`; linked monitors share it): `BarConfig.floating/barGapOf/radiusOf/popupGapOf/edgeGapOf/reserveOf(screen)` are what Bar, BarReserve, PopupHost, Toasts and TrayMenu use. A bar without the key falls back to `Theme.barFloating` (appearance.json `barFloating`, else `theme.toml bar_floating`). Lua: `managed.bar_floating(mon)` / `bar_reserve(mon)` read the same `bars.json` key, used by `apply_bar_gaps` and `pip-reserve.lua`.
- **Compact on fullscreen:** the `Bar.qml` window stays full width; the visible `frame` item (the input `mask`) shrinks to flush while the monitor's active workspace has `hasfullscreen` (quickshell has no such property: read from `lastIpcObject.hasfullscreen`, refreshed after fullscreen/workspace/window raw events), animated by `compactState` with the popup tokens. `BarReserve` is untouched, so tiled windows do not reflow. A real fullscreen covers the Top layer, so the compact look only shows with maximize-style fullscreen. Each Bar publishes its current inset via `Popups.setBarGap`, which PopupHost uses.
- **Respect reserved area** (Settings > Bar > Style, `bars.json` key `respectReserved`; default off = the bar ignores the monitor's `reserved_area` and other exclusive zones and sits at the screen edge). Compositor behaviour found nested: zone-0 surfaces are laid out AFTER all exclusive zones, and a zone>0 surface sits at the usable edge. With the option the BAR is the exclusive surface (`BarConfig.zoneOf`, `BarReserve` hides, no double count) and PopupHost / Toasts / Osd use zone 0 and subtract what the bar consumed (`BarConfig.insetOf`). Not covered: other clients' exclusive zones on the same edge.
- **Transparent when flush** (Settings > Bar > Backdrop, `bars.json` keys `transparentFlush` and `flushPadding`): the bar background fades out while docked or compacted and `Glass.hidden` declares no blur region, so only chips show. **Flush mode = option on AND bar docked** (`BarConfig.flushMode`): Hyprland's outer gap on the bar's side is 0 on that monitor (`managed.lua` `apply_bar_gaps`, per-monitor workspace rules replaced in place at every `layout_apply()`), and the bar height derives from chip height + padding (`BarConfig.heightOf/padSide/reserveOf`, mirrored by `managed.bar_height` for `pip-reserve.lua`). `BarConfig`'s save notifier calls `layout_apply()`. Caveat: with smart gaps off and a lone window, toggling may show the old gap until the next layout pass.
- **Deploy order** when adding keys: theme files -> Hyprland files -> Quickshell files; every intermediate state must load.
- **Pinned video box and gaps** (`hypr/scripts/pip-reserve.lua`, Battlestation only): the pinned PiP/mpv/Twitch box keeps the gap from the screen edge and the bar (`managed.edge_margins()` + `barReserve`; none while smart gaps apply); the video shrinks by the margin and stays 16:9; Hyprland draws borders OUTSIDE `at/size`. Static `rules.lua` rules place it first; pip-reserve corrects on open, first title, heal and every refit trigger (`layout_apply()` -> `pip_bar_changed()`). `pip-smart-rounding-*` rules zero the rounding while smart gaps hold. Pinned windows dragged to the other monitor by workspace switches are healed. Hooks are kept in `__pip_reserve_subs`.
- **Appearance page:** sliders, "No gaps for a single window" switch (`Appearance.setSmartAll` / `setSmartFor`), previews, "Reset to theme defaults" writes `{}`. The page holds `dragging` briefly after a slider move so the Flickable does not steal the drag.
- **Unverified:** real pointer drags, NetPanel confirm/password form and HaVacuum Segmented at larger radii, the single-monitor page layout, per-monitor `m[desc:...]` selectors inside `window_rule match.workspace` and whether `set_enabled` alone re-evaluates open windows on the live compositor (hence the `reload config-only`). Lua harnesses (stub-`hl`, call-log diff) were kept outside the repo; rebuild one if you change managed.lua.

### Popups, motion and animations

- **Popup motion** (`PopupHost.qml`, tokens in `Theme.qml`): open = fade + scale + slide, close = a shorter decelerating variant, chip switch glides the card and cross-fades content. `t` is driven by explicit `openAnim`/`closeAnim` NumberAnimations (not a Behavior), `finishClose()` drops the content. Hyprland's layer fade for `qs-popup` is off (`no_anim` rule), so only QML animates. **Esc closes a popup via a Hyprland bind** (`binds.lua`, non-consuming, runs `qs ipc call popup esc` only while a `qs-popup` or `qs-toast` layer is mapped); never use `keyboardFocus: Exclusive` on PopupHost (breaks click-away and one-click chip switching): it is `None` at map and `OnDemand` after a short `armed` timer (otherwise Hyprland sent `wl_pointer.leave` to the bar and the second click on the same chip was lost). The PopupHost input mask cuts the bar strip out of the scrim's input region so clicking another chip switches popups in one click.
- **Glass during motion:** the card's glass region is the card itself (`Glass.qml` maps it through its transforms each frame). On the fork with `layer_alpha_ref` the glass fades with the card; on stock the glass cannot fade (Quickshell has no `wp_alpha_modifier`), so `Theme.glassFades` is false and `Theme.glassScaleAt(t)` shrinks the glass region instead (Glass.qml drops near-transparent regions).
- **Animations settings** (`Motion.qml`, `SettingsAnimations.qml`, `hypr/hyprland/animations.lua`, managed.lua animations part): keys in `animations.json` (`QS_ANIM_FILE`; IPC `qs ipc call anim get | set <key> <value> | unset <key> | reset popup|hypr|all`; key names, ranges and allowed curve/style values are in `Motion.qml`). Hand-written curves/leaves live in `animations.lua` (edit them THERE); `A.BASE_MS` there and `Motion.baseMs` MUST be equal (Hyprland speed is in ds). Live apply: Motion runs `hyprctl eval "if anim_apply then anim_apply() end"`, which rewrites EVERY leaf from animations.lua (an unset key restores the hand-written value). **Springs:** a spring curve must be referenced as `hl.animation{ spring = "<name>" }` (`bezier =` logs `no such bezier` without raising); springs ignore `speed`, so the factor is baked into per-factor curves `qs_spring_<f*100>`. Workspace animations accept only slide/fade styles. Disabling `fade` also disables inherited fade leaves.
- **Qt animation clock:** Quickshell is started with `QSG_USE_SIMPLE_ANIMATION_DRIVER=1` (`autostart.lua`): Qt's vsync-driven default ran animations too fast on the high-refresh monitor with several screens. A hand-restarted shell needs the same env.
- Nested output at a fractional scale mis-scales every glass blur region (compositor, not a shell bug).

## Per-OS / per-machine config split (Linux primary, macOS secondary)
Shared files stay identical on all machines; machine-specific edits go in their own file so merges stay clean.
- **kitty**: `config/kitty/kitty.conf` is shared; `include ${KITTY_OS}.conf` pulls `linux.conf` or `macos.conf`. `host.py` (geninclude) is for per-hostname overrides. If kitty's font kitten appends a `BEGIN_KITTY_FONTS` block to `kitty.conf`, move it into the OS file.
- **ghostty**: shared `config`, Mac overrides in `macos.conf`, per-machine `host.local` (git-ignored).
- **zsh**: `config/shell/zshrc` branches on `$OSTYPE`/file existence; uses `$HOME`, not absolute paths. Put machine-local lines (installer-appended PATH/completion snippets, per-host aliases) in git-ignored `~/.zshrc.local`, sourced just before zoxide.
- **Hyprland per host**: `host.lua` hostname flags (Battlestation / Workstation / VM), see "The machines".
- **Linux-only** (not linked on the Mac, `install.sh` never runs there): hypr, quickshell, theme engine runs, hyprpaper outputs, launcher. **Mac-only**: `config/aerospace`, `config/karabiner` (`karabiner.json` generated by `generate.py`). `config/theme/out/` is git-ignored and generated on Linux only; the Mac gets the committed default through `bin/theme-seed` (do not run the theme engine on the Mac), the Linux selection lives in the git-ignored `theme.local.toml`.
