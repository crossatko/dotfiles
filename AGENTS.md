# AGENTS.md — dotfiles handbook for AI agents

Read this first. It describes the machines, the repo, the conventions and the current state of the config, so you can continue without re-deriving it. It is a state document, not a changelog (history lives in `git log`); the user's own apps document themselves in their repos (see "Own apps").

## Working rules (mandatory)

### 0. Public repo: never write real setup details

This repo is **public on GitHub**. Never write anything identifying the user's real setup into it: in code, comments, docs, tests, notes, commit messages or screenshots. That means:
- no real hostnames / server or machine names, Tailscale or tailnet names (`*.ts.net`, MagicDNS short names); <!-- privacy-ok -->
- no real URLs or IP addresses (LAN/RFC1918, Tailscale `100.64.0.0/10`), MAC addresses, device serials (monitor descriptions with serials, Bluetooth addresses); <!-- privacy-ok -->
- no usernames, accounts or emails (the user's or anyone's), tokens or keys, personal channel / server / library / calendar names.

Use placeholders instead: `jellyfin.example`, `example-host`, `192.0.2.10`, `user@example.com`, `<token>`. Real values live outside the repo (`~/.config/<tool>/...`, `~/.local/state/...`) or in git-ignored files (`config/hypr/.secrets`). Notes for future agents describe mechanisms, not the user's values. Agents may mention real values to the user in chat, never in repo files.
Enforced by `.githooks/pre-commit` (`git config core.hooksPath .githooks`, set by `install.sh`): it blocks staged lines matching generic patterns plus a private deny-list at `~/.config/dotfiles-private/denylist` (outside the repo). A line containing `privacy-ok` is skipped; `--no-verify` only on the user's explicit decision.

### 1. Global rules

Subagent delegation, change documentation (notes = current state + short caveats, each app documents itself) and the no-attribution rule live in the global `~/dotfiles/CLAUDE.md` (symlinked to `~/.claude*`). They apply here too; they are not repeated in this file.

### 2. Safety rules learned the hard way (repo-specific)

- **Kill Quickshell only by exact PID.** The user's shell is the bare `/usr/bin/quickshell` process. `pgrep -x quickshell` also matches other instances (the Twitch app, probes); `kill`ing by name or relaunching blindly creates duplicates.
- **Don't edit a popup's QML file while that popup is open.** Hot reload crashed Qt's Repeater (segfault) twice. Test in an isolated instance (`quickshell -n -p <dir>`) or with the popup closed.
- Hot reload only works for files already loaded. A new QML type needs a `qmldir` entry AND a full quickshell restart: the running shell does not re-read `qmldir` on hot reload ("X is not a type"; settings pages load lazily, so it only shows when the page opens). Restart: kill the exact quickshell PID, then `hyprctl eval 'hl.exec_cmd("env QSG_USE_SIMPLE_ANIMATION_DRIVER=1 quickshell")'` (`hyprctl dispatch exec` silently does nothing with the Lua config). Changed `.frag`/`.qsb` shaders are not hot-reloaded either. A failed reload keeps the old generation running.
- Don't touch the screen-sharing portal routing (`config/xdg-desktop-portal`). ScreenCast/RemoteDesktop/Screenshot must stay on the Hyprland portal.
- **Secrets:** `config/hypr/.secrets` (`OPENROUTER_API_KEY`, `HA_TV_WEBHOOK_URL`, `HA_GAMESCOPE_WEBHOOK_URL`, Home Assistant `HA_URL`, `HA_TOKEN`, optional `HA_URL_FALLBACK`) is git-ignored; placeholders live in the tracked `config/hypr/.secrets.example`. Never print, log or commit values. WiVRn pairing data is also not tracked.
- **Licensed fonts stay out of the repo.** Font Awesome 7 Pro Sharp is installed in `~/.local/share/fonts/FontAwesomePro/` only.
- Screenshot tips: `grim -g "x,y WxH"`; Hyprland dims unfocused windows (focus first when sampling colours); popups open on the *focused* monitor. The user switches workspaces under you: capture only after checking the active workspace and that no foreign window overlaps.
- Never run `theme.py` from a scratch copy with the real `HOME` (it rewrites links in `~/.config` and `~/.local/share/themes`); set `HOME` in the same command.

## The machines (Linux)

- Arch-based (CachyOS), **Hyprland 0.56 with the native Lua config** (`hl.*`, not a plugin), Quickshell 0.3.2 (QML) for bar/launcher/notifications, hyprpaper, hyprlock.
- **Battlestation** (primary desktop): two 2560x1440 monitors (a 360 Hz OLED main one and a 60 Hz one; the bar lives on the 60 Hz one, below/above depending on layout), RX 9070 XT, runs the user's **Hyprland fork** (glass compositing; see "Own apps"). **Workstation** (work machine): stock Arch `hyprland` 0.56.2, ultrawide 3440x1440 plus a second monitor, RX 5700, no AV1 hardware. Per-host differences live in `config/hypr/hyprland/host.lua` (`$HOSTNAME` is read first, so tests override the host with it) and `hosts/<Host>/`.
- Only `~/dotfiles/config` is live (symlinked into `~/.config`). The Nix files (`flake.nix`, `home.nix`, `hosts/`, `modules/`, `lib/`) are an **old setup**, kept for reference. `install.sh` is the Arch bootstrap (packages, symlinks, hooks); `system/etc/` holds root-owned files the user copies by hand (the agent has no sudo).
- UI font: Paper Mono. Icon font: **Font Awesome 7 Pro Sharp (Regular)** plus Font Awesome Brands (system package) for brand logos.
- Hyprland dispatch: `hyprctl dispatch "hl.dsp.focus({workspace=N})"`; window focus `hl.dsp.focus({window="address:0x..."})`; monitor focus `hl.dsp.focus({ monitor = "DP-3" })`. `hyprctl keyword` is refused with the Lua config. Lua globals can be called with an IIFE: `hyprctl dispatch '(function() if pip_bar_changed then pip_bar_changed() end return hl.dsp.exec_cmd("true") end)()'`. Lua monitor objects expose name/serial/description but **not** model. Hyprland Lua objects (monitors, workspaces, windows) are userdata: test with nil checks, never `type(x) == "table"`. `hl.dsp.window.pin({action=true})` TOGGLES. `Hyprland --verify-config` dumps core, so there is no CLI config check; use `hyprctl configerrors` after a reload.
- `xdg-mime default org.gnome.Nautilus.desktop inode/directory` is set in the untracked `~/.config/mimeapps.list` (otherwise folders open in a terminal); a new machine needs it.
- Dangling `~/.config/{swaync,waybar}` symlinks from old installs can be deleted by hand (Quickshell replaced waybar, swaync, tofi).

## How to test (all features, described once)

- **Isolated shell:** copy `config/quickshell` to a short dir (or start from `git archive HEAD config/quickshell` and copy changed files over it to rehearse hot reload), make a test `HOME` (`.config/theme` and `.local/share/fonts` symlinked, copies of `.local/state/quickshell/*.json`) plus `XDG_{CONFIG,STATE,CACHE,DATA}_HOME` inside it, a short `XDG_RUNTIME_DIR` with `hypr`/`wayland-1` symlinks to the live one, and run `dbus-run-session --config-file=<conf without <servicedir>>  quickshell -n -p <dir>`. Drive it with `quickshell ipc --pid <pid> call ...`; temporary test-only `IpcHandler`s go in the copy only. Env hooks for the state files: `QS_APPEARANCE_FILE`, `QS_ANIM_FILE`, `QS_WALLPAPERS_FILE`, `QS_HYPRCTL` (stub binary), `QS_HA_SECRETS`/`QS_HA_STATE_DIR`, `QS_AI_*`, `QS_TAILSCALE`/`QS_MULLVAD`, `QS_LAUNCHER_NET_FIXTURE`, `QS_WEBAPP_HELPER`, `QS_QUICKGET`, `SCREENREC_*`, `SHOT_*`. A scratch launcher/modal must not take focus (`ModalMenu` grabs exclusive keyboard focus): set `keyboardFocus: None` and an empty mask in the copy. Kill by exact PID, then orphaned poller shells (ppid 1) of the test HOME.
- **Nested compositor** (anything about glass, scale, layers, window rules, wallpapers, GTK/Qt apps): start `Hyprland -c <config copy>` with its own short `XDG_RUNTIME_DIR` (socket paths must be short; `WAYLAND_DISPLAY` absolute if needed), hidden via `hl.dsp.exec_cmd(cmd, {workspace="special:x silent", no_initial_focus=true})` or floated on a monitor, add outputs with `hyprctl output create headless TEST` + `hl.monitor({output='TEST', mode='WxH@60', scale=s})` + `hyprctl reload`. Export the nested `XDG_RUNTIME_DIR` / `HYPRLAND_INSTANCE_SIGNATURE` / `WAYLAND_DISPLAY` (never `ls -t` for the signature; the user may run other nested instances), capture with `grim -o TEST` on the nested socket, and put a solid/checkerboard backdrop window or layer behind translucent things. Headless outputs only render while the nested window is visible. Use `/usr/bin/Hyprland` for stock behaviour, `/usr/local/bin/Hyprland` for the fork. `bars.json` in the test HOME must enable `TEST` (headless outputs have no model, key = name).
- **Never inject synthetic input into the live session.** Real clicks/drags/keys are "not verified" unless the user does them; the nested instance may be driven with `hl.dsp.send_shortcut`, `hl.dsp.cursor.move` or a virtual-pointer client that refuses any socket but the nested one.
- **Unit-level:** `python3 -I config/theme/selftest.py` (extractor, must pass for any wallpaper), `python3 -I -m unittest discover -s config/url-router/tests`, `... -s config/launcher/jellyfin/tests`, `... -s config/quickshell/bin/tests` (webapp helper), `luac5.5 -p` on Lua files, `qmllint`, `qmltestrunner` (offscreen) for pure QML logic (test files kept outside the repo).
- **Measuring bar/chip alignment:** temporary `console.log` of `mapToItem(null,0,0)` + size, `grim -g` crops, per-chip background interpolation; judge on fractional-edge margins, not bbox.

## Theme system (`config/theme`)

- **One place to edit:** `theme.toml` (+ `templates/`). Never hard-code colours in an app config. Details: `config/theme/README.md`.
- `theme.py apply <img>` extracts a palette from the wallpaper (own extractor: wallust/matugen average away small saturated accents), renders templates to `out/`, and live-reloads kitty, ghostty, alacritty, nvim (RPC sockets), zellij, herdr, hyprland/hyprlock/hyprpaper, quickshell, GTK CSS, KDE/qt6ct palette, hue-rotated Adwaita icons (`Wall-Adwaita`), Brave, Thunderbird. Wallpapers: `~/Pictures/wallpapers` (`wallpaper_dirs`), videos `~/Videos/wallpapers` (`video_dirs`). Picker = Settings > Wallpaper & theme, `SUPER+T` (`qs ipc call picker toggle`).
- Layout defaults in `theme.toml [settings]` (`rounding` 0, `gap` 0, `border_size` 2, `bar_floating` false, `smart_gaps` true, `bar_border`, `bar_opacity`) go to `out/palette.json` and drive **Quickshell only**; `out/palette.lua` carries just `wallpaper`, `rounding` and colours, and Hyprland's own values stay hand-written in `hypr/hyprland/` (keep the two in sync when changing a default). User overrides live in `appearance.json` (see Appearance).
- **Per-host output:** GTK3/GTK4 CSS, `kvantum.kvconfig` and `brave-glass.css` are rendered into git-ignored `out/host/` because the fill alpha depends on the compositor (0.3 on solid_glass, `bar_opacity` on stock). A pull touching `config/theme/` re-renders via `.githooks/post-merge` / `post-rewrite` -> `theme-render` (`THEME_RENDER_SKIP=1` skips). After pulling on a new host run `~/.config/theme/theme.py render` once (relinks GTK CSS; until then GTK apps use stock Adwaita). On macOS the engine never runs (`theme.py` exits 0 on darwin).
- Qt: `QT_QPA_PLATFORMTHEME=kde` (`env.lua`), style Kvantum theme `Wall` (`theme.toml qt_style = "kvantum"`; falls back to Fusion with a message if Kvantum is missing, install `kvantum` + `kvantum-qt5`), icons `Wall-Adwaita-Qt`. Brave/Chromium dialogs use the GTK theme `Wall` via `GTK_THEME`; portal FileChooser = `xdg-desktop-portal-gnome`.
- Known limits: GTK4/libadwaita cannot restyle open windows; Brave only picks the theme up while closed (the `~/.local/bin/brave` shim applies it); `theme.toml` `thunderbird`/`thunderbird_radius`, `brave_mode`, `gtk_glass*`, `qt_symbolic_icons` are the knobs.
- `render_all()` once rewrote `out/hyprpaper.conf` with `~` TV-wallpaper paths; the committed generated `hyprpaper.conf` is kept as is (it contains monitor serials, user decision).

### Toolkit glass (GTK4, GTK3, Qt/Kvantum, Brave, Firefox, Thunderbird)

- **Principle:** the compositor already applies tint / darkening / saturation / refraction behind any translucent window with the shell cards' values, so app CSS paints only the card fill (`Theme.cardFill` 0.3 on solid_glass; `bar_opacity` 0.55 on plain blur, NOT the shell's `bar_opacity + 0.3`) plus per-part offsets (`theme.toml gtk_glass_{chrome,header,sidebar,view,popover,dialog,control}`, `gtk_glass_fill` overrides the base, `gtk_glass` false = opaque). Repeating tint/darkening in CSS would apply it twice. Glass slider changes reach running GTK apps live; CSS changes (palette, blur variant) need `theme.py apply` and an app restart. `theme.py hypr_solid_glass()` and `Theme.qml` use the same test: keep in sync.
- **GTK4/libadwaita:** `~/.config/gtk-4.0/gtk.css` -> `out/host/gtk4.css` (template `gtk4.css`, link set in `deploy()`), overrides libadwaita named colours with alpha. **Blur needs `backdrop-filter`:** GTK >= 4.22 creates an empty `ext-background-effect-v1` blur region and Hyprland treats that as "no blur", so `window { backdrop-filter: blur(12px) }` and popover rules are required. Do not also set `--*-bg-color` variables at user priority (ghostty sets `:root --window-bg-color` itself). User CSS outranks theme CSS regardless of specificity, so every state that changes a fill must be listed. Needs GTK >= 4.22; nautilus list view, Papers, Epiphany, light scheme unverified. `nautilus --new-window` attaches to a running user instance: test under `dbus-run-session`.
- **GTK3:** `~/.config/gtk-3.0/gtk.css` -> `out/host/gtk3.css`, scoped to `window.csd` (Gecko reads system colours from unrealised contexts without `.csd`, so Firefox/Thunderbird are untouched); menus stay opaque; windows without a header bar (server-side decorated, no `.csd`) stay opaque. GTK3 inlines Adwaita colours, so explicit selectors, not `@define-color`.
- **Qt:** a palette alpha alone stays opaque; Kvantum `translucent_windows` (via `write_kvantum_theme()`: KvFlat recoloured to the palette + `out/host/kvantum.kvconfig`) sets `WA_TranslucentBackground`; video apps and quickshell are `opaque=`. `~/.config/Kvantum/kvantum.kvconfig` selects `Wall`. Metrics of Qt and GTK3 copy libadwaita's measured sizes (header bar 46, buttons 34, entries 34, sidebar rows 36, switch 46x26, popover items 32, 9/12 px corners; see `kvantum_svg.py`, `templates/kvantum.kvconfig`, `templates/gtk3.css`). Kvantum quirks that cost time: push buttons add +4 px over frame+text, default button label colour cannot be set, item-view margins are capped at 6 px, unfocused windows request `itemview-*-inactive`. Qt icons: `gen_qt_icons()` builds `Wall-Adwaita-Qt` (Adwaita symbolic + Breeze Dark fallbacks); toolbars icon-only 16 px. Limits: icon-only QPushButtons stay 52 px, no Qt switch widget, Dolphin draws some own geometry, Qt5 unchecked.
- **Brave (GTK mode, `brave_mode = "gtk"`):** the tab strip uses the GTK `headerbar`/`.titlebar` background including alpha (must be set for `:backdrop` too, else the unfocused window is opaque); the toolbar/omnibox row stays opaque in Chromium. Requires `browser.custom_chrome_frame = true` (else the surface is opaque and the strip solid); `apply_brave()` (run by the shim while Brave is closed) writes it and `extensions.theme.system_theme = 1`. `bin/brave` exports `GTK_THEME=Wall-Glass:dark` (`~/.local/share/themes/Wall-Glass` = Wall + `brave-glass.css`). Tab/toolbar colours come from specific GTK nodes (`window.background` = toolbar and active tab, `label` = active tab text, `.titlebar label` = inactive tabs, `.view` = omnibox); the omnibox focus ring and the toolbar's top corner triangles come from Chromium's seed-colour pipeline, not GTK (`brave_gtk_seed` optional; corner colour is a fixed dark tone of the seed hue, no fix). `brave_mode = "seed"` restores the old seed-colour theme.
- **Firefox:** `config/firefox/userChrome.css` + `user.js` linked by `install.sh` into the install-default profile; translucent header via the real variables of Firefox 158 (`--toolbox-background-color`, `--toolbar-background-color`, `--navbar-tint`, ...), content forced opaque; `--window-radius` (12px) is a hard-coded copy of the Appearance radius (update by hand), tabs concentric with it. Restart needed; selectors may break on updates.
- **Thunderbird:** `templates/thunderbird-user{Chrome,Content}.css` (+ shared `tb-vars.css`) -> `out/` -> `<default profile>/chrome/` by `apply_thunderbird()` and a marked `// >>> theme` block in `user.js` (`toolkit.legacyUserProfileCustomizations.stylesheets`); runs on every `render`/`apply`; restart TB; a foreign userChrome is moved to `*.pre-theme` once. Palette on TB's own tokens, HTML mail untouched. Selectors can break on TB updates (re-diff `omni.ja` `messenger/colors.css`). Unverified: dialogs, IMAP-only UI, light theme. TB test rig: throwaway profile with Local Folders (`storeContractID=@mozilla.org/msgstore/berkeleystore;1`, absolute `directory`), `--no-remote --marionette`, UI driven by a temporary experiment WebExtension.
- **Calendar data** (CalPanel -> `bin/calendar-events`) comes from Thunderbird's `cache.sqlite` (read-only copy): only calendars with "Offline support" enabled appear; the popup footer names the uncached ones. Fetching Google CalDAV directly was ruled out (needs TB's OAuth token).

### Wallpapers (per monitor, videos, links)

- **State:** `${XDG_STATE_HOME:-~/.local/state}/theme/wallpapers.json` (host-local, written only by `theme.py`; `THEME_WALLPAPERS_FILE` / `QS_WALLPAPERS_FILE` override): `{"version":1,"primary":"<key>","monitors":{"<key>": "<img>" | {video, mode, still, play, wind, ease}},"primary_video":{...},"links":[[a,b],...],"optimize":..,"optimize_speed":..}`. Key = monitor description as Hyprland reports it (else connector). The **primary** monitor's wallpaper is the theme source (`wallpaper` in `theme.toml`); `primary` unset = monitor at 0,0; a monitor without an entry shows the primary's wallpaper. Unplugged monitors' entries are kept.
- **CLI:** `theme.py apply <file> [--monitor k]... [--mode once|loop] [--play S --wind S --ease S]`, `clear k...`, `primary k`, `link a b [--from k]`, `unlink a b`, `video start|stop|restart|sync|status|thumb(s)|replay|optimize|optimize-speed|loopinfo|hwdec`. A non-primary apply only re-renders `out/hyprpaper.conf` and live-sets the output with `hyprctl hyprpaper wallpaper "<selector>,<path>,cover"`; **the selector must match the config block's** (`desc:<key>` for description keys, connector only for connector keys; a mismatch exits 0 silently, `live_set_wallpaper()` polls `listactive` and restarts hyprpaper). `templates/hyprpaper.conf` has `{{monitor_preloads}}` / `{{monitor_blocks}}` (later blocks win) plus a catch-all block; `tv_wallpaper` falls back to the main wallpaper when the file is missing. hyprpaper does not hot-reload its config; a full apply restarts it.
- **Settings page** (`SettingsWallpaper.qml`, `WallpaperMonitorCard.qml`, `WallpaperTile.qml`): header = theme-source name + palette swatches; monitor cards (2+ screens) pick the edited monitor ("Follow primary" / "Make primary"); Images / Videos tabs; Videos tab has Play once / Loop, Optimize toggle + speed, "Play for" / "Wind down" / "Ease-in" sliders that apply on RELEASE (cancel + re-bake). Session memory (tab, edited monitor, mode) via the `memory` page hook. Test hooks: `qs ipc call wallpaperpage tab images|videos`, `... monitor <key>`.
- **Monitor links:** linked monitors always change together (wallpaper apply/mode/timing/follow go to the whole group; "Make primary" stays per monitor). Bars: links live in `bars.json` under reserved key `"_links"`; linked monitors share on/off, edge and layout (`BarConfig.set`/`BarWidgets.store` write every key of the group; the last-bar rule is about the group). UI: `MonitorCardRow.qml` + `MonitorLinkButton.qml`; each card gets round cut-outs around link buttons via `NotchMask.qml` + `shaders/notchmask.frag(.qsb)` (SDF stroke, `Theme.controlGap` 6 spacing scale, card `gap` 30 derived from it). `NotchMask` is a qmldir type: live restart needed.
- **Video wallpapers** (mpvpaper 1.9 + libmpv): one `mpvpaper -l bottom -o "<opts>" <connector> <file>` per output (hyprpaper stays on `background`, so the video is always above the still and below windows), pid files + logs in `$XDG_RUNTIME_DIR/theme-video/`, stop = SIGTERM/SIGKILL only if `/proc/<pid>/comm` is `mpvpaper`, flock serialises syncs. `scripts/start-hyprpaper.sh` runs `theme.py video start` after hyprpaper; `autostart.lua` re-syncs on `monitor.added/removed`. `MPV_OPTS` carry `load-scripts=no` so `mpv-mpris` does not turn wallpapers into MPRIS players (explicit `scripts=winddown.lua` still loads). No `-p` auto-pause (unreliable on Hyprland). Players keep decoding behind windows; looping 4K60 sources are the worst case (prefer 24-30 fps or play-once).
  - **Once vs loop:** once = plays, holds the last frame (the login animation); stills (`video_still()`, ffmpeg, cached in `$XDG_CACHE_HOME/theme/video`) feed the palette and the hyprpaper image under the player. The hold point skips a black tail (`video_hold()`, blackdetect on the tail); mpv's `end=` is exclusive, so the still is the frame BEFORE t_stop. Timed play-once: `play` S then raised-cosine wind-down over `wind` S (covers wind/2 of media, `t_stop = play + wind/2`, `WIND_AVG` shared by theme.py / `mpv/winddown.lua` / QML), no `play` = full length. Runtime ramp steps through source frames (choppy), so with Optimize on a per-monitor **baked file** is built (see below). Runtime smoothing is off above 145 Hz (it cost +7 points GPU at 360 Hz); mpvpaper presents at the output's frame callbacks, so `display-fps-override` must equal the real refresh or playback speed scales wrongly (`winddown-fps`).
  - **Optimize for monitor (default on):** per (video, monitor) HEVC Main copy (H.264 fallback via `out_codec()`; `hevc_vaapi` QP 16, libx265 crf 14; encoders and hardware decode are probed per machine and cached under `$XDG_RUNTIME_DIR/theme-video/probe-*`; `THEME_FORCE_NO_HWDEC`, `THEME_OUT_CODEC`, `THEME_FORCE_ENCODER` simulate other machines) in `$XDG_CACHE_HOME/theme/video/opt/` (LRU 4 GB), scaled to the monitor's physical pixels, fps = largest of 25/30/40/45/50/60 dividing the refresh. `hevc_vaapi` + `hvc1` needs `-bsf:v extract_extradata` (else undecodable). Apply plays the original at once, the copy swaps in at an invisible point; if the source has no hardware decode here (AV1 on the RX 5700) the still stays until the copy is ready (`video_wait_for_copy`). Stills/palette always come from the original. Speed modes Background (default, SCHED_IDLE) / Balanced (60 %) / Fast; switching signals the runner (SIGUSR1) and re-prioritises live. Cancelling on slider release kills only the stale job's ffmpeg/RIFE process groups.
  - **Baked wind-down and replay bursts:** a baked file = first play + a chain of short **bursts** (ease-in 0 -> 1 then cosine wind-down, >= 1 s each; sidecar `<bake>.json`), RIFE v4.14 (`rife-ncnn-vulkan` from the AUR, models in `/usr/share/rife-ncnn-vulkan`; fallback ffmpeg `minterpolate`) synthesising in-between frames at F fps (60, or 120 only for >= 119 fps sources on a whole-multiple refresh). Every workspace switch (except special workspaces) plays the next burst and holds (`scripts/video-replay.lua` -> `mpv/replay.py <connector>` -> mpv IPC `winddown-restart`; ignored while a burst plays); station survives a player restart (`<runtime>/theme-video/<conn>.station`); the launcher also replays when the focused workspace is empty. Loops wrap around (K bursts per loop, capped by `burst_kmax`), non-loop clips restart from burst 0 with a fade segment when the cut is not clean. RIFE runs as a few long-lived directory-mode processes (`-j 2:1:2`, workers sized by free VRAM, OOM halves them; arbitrary steps via the hard-linked slot trick; nearest source frame where the output steps >= 1 source frame). Bakes ignore load (user never changes wallpapers while gaming); `THEME_BAKE=0` disables. Colour: the PNG round trip must use the source's matrix/tags (`RGB_UP`, `bake_rgb_down`) or luma shifts; every concat part uses `-video_track_timescale 90000`; `BAKE_VERSION`/`OPT_VERSION` are in the cache keys. Do not compare `psnr` across files of different frame counts.
  - **Caveats:** baking cost grows with burst count (raycast 4K120 on a 60 Hz monitor ~95-350 s); a failed/pending encode leaves the original running; monitor disconnect can segfault mpvpaper (stale pid file reaped by the next sync); unreadable videos show an "unreadable" cell and `apply` exits 1; changing a monitor's refresh later needs `theme.py video restart`; untagged videos can get a different matrix in the still. Not verified: the RX 5700 path, nvenc/qsv, real pointer drags on the Settings sliders.
  - Try it live: `python3 ~/.config/theme/theme.py render`, Settings > Wallpaper & theme, `theme.py video status`, `hyprctl layers -j` (mpvpaper must be in layer level 1).

### Shared building blocks (use these, do not hand-roll)

`Icon` (FA glyph Label; bar chips use `BarIcon`), `PanelHeader`, `ListRow` + `RowText` + `RowState` (list cards; fixed 22 px state column: check, pulsing ellipsis, plug on hover), `Notice` (confirmation / error / empty / setup steps), `LevelRow` (icon + `Slider` + value), `Meter`, `Segmented`, `SettingRow`, `Btn`, `Toggle` (only on main-section headers; item rows use `RowState`), `ModalMenu` + `KeyBadge` (keybind-opened layer modal, used by `Launcher`; `fixedScreen`, `respectReserved`, `focusItem`, `animated`), `PopupRegistration` (registers click-away things with `Popups`), `HoverGlow`, `SwipeDismiss`, `Icons.volumeGlyph`. Recipes: new popup = file with `PanelHeader` + sections, name in `PopupHost`'s content switch and width map, chip calls `bar.pop`, qmldir entry; new list row = `ListRow` + `RowText` + `RowState`/`Btn`; click-away non-popup = `PopupRegistration`.
- **HoverGlow:** pointer-following radial light, fill colour = the parent's current fill (opaque), strength by luminance, reach = max(3 x height, 0.7 x width); pointer tracking is a passive `HoverHandler` re-parented to the item (a child control's hover would otherwise drop `containsMouse`). `glow.hovered` is also what flat hover tints use. Built into ListRow/Tile/Btn/Toggle/Segmented, pickers, HA tiles, CalPanel cells, NotifCard buttons, Settings sidebar/cards/chips. Not on Sliders (user decision) or text links.
- **Slider:** square 16x16 handle, radius `min(8, Theme.radius)`; pointer x maps through the handle's own travel (`(px - 8) / (width - 16)`) so the pointer stays on the handle centre; Meter fill ends at the handle centre; after release a stepped value glides to its snapped position. `wheel: false` on every Slider inside scrolling Settings pages (a wheel over a timing slider once triggered a full theme apply). While pressed it grows into a 28 px in-app **glass lens** (`shaders/sliderlens.frag` + committed `.qsb`; build `/usr/lib/qt6/bin/qsb --qt6 -o sliderlens.frag.qsb sliderlens.frag` in `shaders/`; Qt caches a ShaderEffect shader per URL for the process life, restart after changing it): a `ShaderEffect` re-parented to the host card's parent, fed by a child `ShaderEffectSource` (must be a visual child, a parentless source segfaulted on window hide) that hides and redraws the card; optics are a port of the fork's `solidglassfinish.frag` driven by `GlassTuneCtl.values` (fork) or `defaults()` (stock); no lens on the software scene graph or a shader error (the handle just scales). With the battlestation's current glass.json (specular 0, sheen 0, frost 0) the lens has no rim.
- **Qt/QML gotchas:** never use endless shell loops in a `Process` (they orphan to systemd on restart): poll with `Timer` + `FileView.reload()` (works on /proc) or one-shot Processes; no inline `component X:` in a file the running shell already loaded without one (hot reload fails "X is not a type"); never bind an item's own `visible` to its `visibleChildren` (latches off); a property named like an id shadows it; `clip: true` clips to the bounding box, not the rounded shape (use a MultiEffect mask for media art / thumbnails when radius > 0); `layer.effect` shader masks are not clipped by hot reload; singletons are not warmed in isolated instances; `Chip`'s hover MouseArea sits at `z: -1` so child MouseAreas get clicks; Binding-loop-prone `x` reading laid-out values goes into a delayed `Binding` (Chip row x); a `Behavior` easing must never be a binding that flips on close (use explicit open/close animations); a QML function named `closed` clashes with the window signal.

### Bar chip and icon alignment

- Tokens in `Theme.qml`: `chipHeight` 28 (= barHeight - 2*barPad), `chipPadX` 10, `chipGap` 6, `chipIcon` 16. `Chip.qml`: content <= one icon box wide gives a 28x28 square; otherwise `ceil(content) + 2*padX`, row at a whole-pixel x; `implicitWidth = max(chipHeight, content + 2*padX)`. **Never set `implicitWidth` on a chip, never use `BarLabel` with the icon font.** Add a chip: `Chip { BarIcon { text; color } BarLabel { ... } }`.
- `BarIcon` is a fixed 16x16 box with the glyph's *rasterised* ink centred (`InkMeter`: a Canvas that draws the string with the same font and scans alpha; x exact and not snapped, vertical baseline on a whole DEVICE pixel). `InkMeter.dpr` = `QsWindow.window.devicePixelRatio` (fractional; `getImageData` returns raw device pixels, which broke every scale != 1 until fixed). `Chip` centres the row on the visible ink of its first/last item. Don't read child `x`/`width` inside those bindings (binding loop). Measured: horizontal |L-R| <= 0.45 px at scale 1, <= 0.16 at others; vertical residual <= ~1 px (whole-pixel baseline; a fractional baseline smears horizontal bars). Tray bitmaps keep their own padding. 1.5 is not a valid scale on 2560x1440 (Hyprland snaps to 1.6). No `QT_SCALE_FACTOR*` is set.

### Appearance (radius, gaps, floating bar)

Settings > Appearance changes corner radius, gaps, border, docked/floating bar and smart gaps (globally and per monitor), in Hyprland AND Quickshell, live.
- **Data:** `${XDG_STATE_HOME:-~/.local/state}/quickshell/appearance.json`, e.g. `{"version":1,"radius":12,"gap":10,"edgeGap":10,"border":2,"barFloating":true,"smartGaps":true,"smartMonitors":{"<monitor key>":false}}`. Missing key = theme default; `{}`/no file = all defaults. Clamps (QML writer and Lua reader alike): radius 0-32, gap 0-32, edgeGap 0-40 (unset = gap), border 0-6, `smartMonitors` max 16 entries, keys 1-96 printable ASCII without `"` and `\`, values true/false, any invalid entry voids the whole map; file cap 4 KiB; non-objects/FIFOs/directories fall back to defaults. Precedence: Quickshell `appearance.json` > `theme.toml [settings]` > fallbacks; Hyprland `appearance.json` > hand-written config. `gaps_in = round(gap/2)`, `gaps_out = edgeGap ?? gap`. Monitor key = description as Hyprland reports it (connector as fallback, same rule `Appearance.monitorKey()` / `M.monitor_key()`); identical monitors without serial share a key.
- **Writers/readers:** only `Appearance.qml` writes (400 ms debounce, then `hyprctl eval "if layout_apply then layout_apply() end"` after 250 ms; `hyprctl reload config-only` instead when `smartGaps`/`smartMonitors` changed; hand edits are picked up by a FileView watch). The shell makes no hyprctl call at start. `theme.py` never touches the file. Hyprland reads it at every config load.
- **`hypr/hyprland/managed.lua`** holds everything Appearance does in Hyprland (never put hand-written settings there): loaded by `pcall(require, "hyprland.managed")` after `permissions`, before the scripts (`pip-reserve` requires it again; the module sets `package.loaded` first). It applies only the keys that are set (`hl.config` each in `pcall`), remembers a baseline read with `hl.get_config` and restores it on reset, and registers the smart-gaps rules (all registered once, flipped with `set_enabled`): a catch-all set (`w[tv1]`/`f[1]` workspace rules + no-border/no-rounding window rules) and one set per connected monitor (`m[desc:<description>]...`, falling back to `m[<connector>]` when `desc:` would not select exactly that monitor: prefix matches, identical descriptions, brackets/edge spaces), max 32 sets; hot-plug via `hl.on("monitor.added"|"monitor.removed"|"hyprland.start")`; subscriptions are kept in globals and removed at the next load so a reload does not stack them. Global `layout_apply()` never raises. A Lua error at config load disables the rest of the config, so everything is `pcall`ed and clamped. Reload pitfalls: Hyprland auto-reloads on save, so every file must load alone; managed.lua must stay after the hand-written modules. Same file also does animations (`anim_apply()`) and `apply_glass_layer_alpha()`.
- **Theme.qml API:** mirrors `radius` (R), `gap`, `gapIn`, `gapOut`, `borderSize`, `barFloating`, `smartGaps`; bar `barGap` (floating ? gapOut : 0), `barRadius`, `barPad` 6, `barReserve` (= barHeight + barGap); popups `popupGap` (floating max(4, gapOut), docked 8) and `edgeGap` (floating gapOut, docked 12) — **`Theme.edgeGap` is NOT the user's `edgeGap` key (that is `Theme.gapOut`)**; concentric rule `inner(outer, inset) = outer <= 0 ? 0 : max(min(outer, 4), outer - inset)`; named radii `radiusChip = inner(R,6)`, `radiusItem = inner(R,12)`, `radiusPage = inner(R,18)`, `radiusDeep`, `radiusModal`. Pills (toggles, tracks, dots) keep `min(h/2, ...)`. `Btn` takes `outerRadius` / `inset` and clamps to `floor(height/3)`; buttons not directly in a popup card set both (Settings close/page buttons inset 18, monitor-card buttons `radiusPage`/9, chip eye buttons inset 6). Accent stripes run from `y = radius` to `height - radius`.
- **Docked vs floating:** docked = margins 0, radius 0, reserve = barHeight (the committed look); floating = bar `gapOut` from the edges with radius R and reserve barHeight + gapOut. Toasts top = `edgeGap + barReserve` with a top bar, OSD bottom = `70 + barReserve` with a bottom bar, TrayMenu `popupGap` from a floating bar.
- **Deploy order** when adding keys: theme files -> Hyprland files -> Quickshell files; every intermediate state must load.
- **Pinned video box and gaps** (`hypr/scripts/pip-reserve.lua`, battlestation): the pinned PiP/mpv/Twitch box keeps gaps_out from the right screen edge and the bar (`managed.edge_margins()` + `barReserve`; 0 while smart gaps apply, i.e. exactly one visible tiled window on the monitor's active workspace (groups count once; maximized counts, fullscreen does not) or a maximized window); the reserved strip stays 1588 wide, the video shrinks by the margin and stays 16:9; Hyprland draws borders OUTSIDE `at/size` (pinned windows have border 0). Static `rules.lua` rules place it docked-bar/gap-0 first; pip-reserve corrects on open, first title, heal and every refit trigger (`layout_apply()` -> `pip_bar_changed()` refits). `pip-smart-rounding-1..3` rules zero the rounding while smart gaps hold. Pinned windows dragged to the other monitor by workspace switches are healed (unpin, move, reposition, pin). Hooks are kept in `__pip_reserve_subs`; unknown event names are skipped. Not changed: `pip-orientation.lua` (workstation geometry), Steam OSK rule, Twitch popout chat rule, `switch-workspace.lua`.
- **Appearance page:** sliders for radius / border / gap / edge gap (+ "Separate edge gap" toggle), Docked|Floating, "No gaps for a single window" main switch (`Appearance.setSmartAll`, clears `smartMonitors`) with one row per monitor when 2+ screens (`setSmartFor`, "(default)" while no own entry), nested-sample and mini-desktop previews, "Reset to theme defaults" writes `{}`. The page holds `dragging` for 300 ms after a slider move so the Flickable does not steal the drag.
- **Unverified:** real pointer drags, NetPanel confirm/password form and HaVacuum Segmented at R > 0, the single-monitor page layout, per-monitor `m[desc:...]` selectors inside `window_rule match.workspace` and whether `set_enabled` alone re-evaluates open windows on the live compositor (hence the `reload config-only`). Lua harnesses (`managedtest.lua`, `piptest.lua`, stub-`hl`, equivalence by call-log diff) were kept outside the repo; rebuild one if you change managed.lua.

### Popups, motion and animations

- **Popup motion** (`PopupHost.qml`, tokens in `Theme.qml`): open = fade + scale 0.96 -> 1 + 10 px slide, 200 ms base (OutCubic); close = 0.75 x open, same family decelerating; chip switch glides card x/width/height with the open curve and cross-fades content (35 % / 65 %). `t` is driven by explicit `openAnim`/`closeAnim` NumberAnimations (not a Behavior), `visible: active || t > 0 || closeAnim.running`, `finishClose()` drops the content. Content is a Loader at the target size inside an Item sized to the animating card; Behaviors only run while `morphing`. Hyprland's layer fade for `qs-popup` is off (`no_anim` rule), so only QML animates; `layer.enabled` only during open/close. **Esc closes a popup via a Hyprland bind** (`Escape`, non-consuming, runs `qs ipc call popup esc` only while a `qs-popup` layer is mapped); never use `keyboardFocus: Exclusive` on PopupHost (breaks click-away and one-click chip switching). `keyboardFocus` is `None` at map and `OnDemand` after a 150 ms `armed` timer (otherwise Hyprland sent `wl_pointer.leave` to the bar and the second click on the same chip at rest was lost). The PopupHost input mask cuts the bar strip out of the scrim's input region (`barStrip` subtracted) so clicking another chip switches popups in one click.
- **Glass during motion:** the card's glass region is the card itself (`Glass.qml` maps it through its transforms each frame). On the fork build with `layer_alpha_ref` the glass fades with the card (per-pixel by the surface alpha); on stock/older builds the glass cannot fade (solid_glass alpha = blurA x overallA, Quickshell has no `wp_alpha_modifier`), so `Theme.glassFades` is false and `Theme.glassScaleAt(t)` shrinks the glass region about the card centre below `glassTailFrom` 0.15 to nothing at t = 0.005 (Glass.qml drops regions under opacity 0.004). Toast and OSD windows follow: with solid_glass the toast layer window height comes from the cards' full heights (`slot.fullHeight`, grows only while toasts are up) so the compositor never stretches a stale buffer.
- **Animations settings** (`Motion.qml`, `SettingsAnimations.qml`, `hypr/hyprland/animations.lua`, managed.lua animations part): keys in `animations.json` (`QS_ANIM_FILE`; IPC `qs ipc call anim get | set <key> <value> | unset <key> | reset popup|hypr|all`): `popupSpeed` 0.25-10, `popupCurve` cubic|quint|expo|back|linear, `popupStyle` scale|slide|fade|none, `launcherMotion` (default false; true = `ModalMenu.animated` with the popup tokens), `hyprEnabled`, `hyprSpeed`, `hyprCurve` config|smooth|snappy|overshoot|linear|spring, per group (windows, layers, fade, workspaces, specialWorkspace, border) Enabled/Speed/Curve. Hand-written curves/leaves live in `animations.lua` (edit them THERE); `A.BASE_MS` there and `Motion.baseMs` MUST be equal (1x = 200 ms on both sides; Hyprland speed is in ds). Live apply: Motion runs `hyprctl eval "if anim_apply then anim_apply() end"`, which rewrites EVERY leaf from animations.lua (an unset key restores the hand-written value). Speed sliders share `Motion.speedRange` = `M.ANIM_SPEED` and a log mapping with 1x tick. **Springs:** a spring curve must be referenced as `hl.animation{ spring = "<name>" }` (`bezier =` logs `no such bezier` without raising); springs ignore `speed`, so the factor is baked into per-factor curves `qs_spring_<f*100>` (stiffness f^2, dampening f). Workspace animations accept only slide/fade styles (specialWorkspace = fade). Disabling `fade` also disables inherited fade leaves.
- **Qt animation clock:** Quickshell is started with `QSG_USE_SIMPLE_ANIMATION_DRIVER=1` (`autostart.lua`): Qt's vsync-driven default ran animations ~1.4x too fast on the 360 Hz monitor with several screens; the simple driver is correct and keeps the native frame rate. A hand-restarted shell needs the same env.
- **Slider glass, toasts, swipe:** `SwipeDismiss` (DragHandler on the card, 38 % of width or a >= 900 px/s flick dismisses, spring-back/fly-off use the popup tokens; offset is a `Translate`, so Toasts' own `x` animation and Glass.qml's transform collection keep working; toast timeout pauses while swiping; `NotifCard.dismiss()` is the single dismiss path; the CenterPanel list uses per-row gaps so the gap collapses with the row). Nested output at scale 0.5 mis-scales every glass blur region (compositor, not a shell bug).

### Network, VPN, Bluetooth, audio

- **Tailscale** section (network popup, folded by default via `FoldSection`): `tailscale up/down` (no flags), state lines, peer list (self first, online first; name = first label of `DNSName`, the admin-console machine name), click expands details, "Use as exit node". ## Per-OS / per-machine config split (Linux primary, macOS secondary)
Shared files stay identical on both machines; machine-specific edits go in their own file so merges stay clean.
- **kitty**: `config/kitty/kitty.conf` is shared (generic `font_family family="Paper Mono"`); `include ${KITTY_OS}.conf` pulls `linux.conf` or `macos.conf` (option-as-alt, title bar, brew variable-font spec, `clear_all_shortcuts yes` + only cmd+c/cmd+v and font size (cmd+plus/equal/minus/0, all windows) re-mapped: no kitty tabs/windows/layout keys, zellij does all of it; cmd+q quits via the app menu only if kitty still lists it, unverified). `host.py` (geninclude) is for per-hostname overrides. If kitty's font kitten appends a `BEGIN_KITTY_FONTS` block to `kitty.conf`, move it into the OS file. `kitty.conf.bak` was a stale kitty backup, removed.
- **zsh**: `.zshrc` branches on `$OSTYPE`/file existence (brew, plugin dirs, Android SDK, `update()`); `$HOME` instead of absolute paths. Put machine-local lines (installer-appended PATH/completion snippets, per-host aliases) in git-ignored `~/.zshrc.local`, sourced just before zoxide.
- **Linux-only** (not linked on mac, `install.sh` never runs there): hypr, quickshell, theme engine runs, hyprpaper outputs, launcher. **mac-only**: `config/aerospace`, `config/karabiner` (`karabiner.json` generated by `generate.py`). `config/theme/out/*` is generated on Linux only; the Mac just reads the committed outputs, so no split needed (do not run the theme engine on the Mac).
