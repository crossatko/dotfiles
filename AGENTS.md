# AGENTS.md — dotfiles handbook for AI agents

Read this first. It describes the machine, the repo, the conventions, and what has already been built, so you can continue without re-deriving it.

## Working rules (mandatory)

### 0. Public repo: never write real setup details

This repo is **public on GitHub**. Never write anything identifying the user's real setup into it: in code, comments, docs, tests, notes, commit messages or screenshots. That means:
- no real hostnames / server or machine names, Tailscale or tailnet names (`*.ts.net`, MagicDNS short names); <!-- privacy-ok -->
- no real URLs or IP addresses (LAN/RFC1918, Tailscale `100.64.0.0/10`), MAC addresses, device serials; <!-- privacy-ok -->
- no usernames, accounts or emails (the user's or anyone's), tokens or keys, personal channel / server / library names.

Use placeholders instead: `jellyfin.example`, `example-host`, `192.0.2.10`, `user@example.com`, `<token>`. Real values live outside the repo (`~/.config/<tool>/...`, `~/.local/state/...`) or in git-ignored files (`config/hypr/.secrets`). Notes for future agents describe mechanisms, not the user's values. Agents may mention real values to the user in chat, never in repo files.
Enforced by `.githooks/pre-commit` (`git config core.hooksPath .githooks`, set by `install.sh`): it blocks staged lines matching generic patterns plus a private deny-list at `~/.config/dotfiles-private/denylist` (outside the repo). A line containing `privacy-ok` is skipped; `--no-verify` only on the user's explicit decision.

### 1. Global rules

Subagent delegation, change documentation and the no-attribution rule live in the global `~/dotfiles/CLAUDE.md` (symlinked to `~/.claude*`). They apply here too; they are not repeated in this file.

### 2. Safety rules learned the hard way (repo-specific)

- **Kill Quickshell only by exact PID.** The user's shell is the bare `/usr/bin/quickshell` process. `pgrep -x quickshell` also matches other instances (the Twitch app, probes); `kill`ing by name or relaunching blindly creates duplicates.
- **Don't edit a popup's QML file while that popup is open.** Hot reload crashed Qt's Repeater (segfault) twice. Test in an isolated instance (`quickshell -n -p <dir>`) or with the popup closed.
- Hot reload only works for files already loaded. A new QML type needs a `qmldir` entry; a new *top-level* file may need a restart.
- Don't touch the screen-sharing portal routing (`config/xdg-desktop-portal`). ScreenCast/RemoteDesktop/Screenshot must stay on the Hyprland portal.
- **Secrets:** `config/hypr/.secrets` (Twitch `TWITCH_SECRET`, `TWITCH_CLIENT_ID`, Home Assistant `HA_URL`, `HA_TOKEN`) is git-ignored; placeholders live in the tracked `config/hypr/.secrets.example`. Never print, log or commit values. WiVRn pairing data is also not tracked.
- **Licensed fonts stay out of the repo.** Font Awesome 7 Pro Sharp is installed in `~/.local/share/fonts/FontAwesomePro/` only; the repo is public on GitHub.
- Screenshot tips: `grim -g "x,y WxH"`; Hyprland dims unfocused windows (focus first when sampling colours); popups open on the *focused* monitor.

## The machine

- Arch-based (CachyOS), **Hyprland 0.56 with the native Lua config** (`hl.*`, not a plugin), Quickshell 0.3.2 (QML) for bar/launcher/notifications, hyprpaper, hyprlock.
- Two monitors on the "battlestation" host: `DP-3` (main, y=0) and `DP-1` (second, below it), 2560x1440. Per-host differences live in `config/hypr/hyprland/host.lua`.
- Only `~/dotfiles/config` is live (symlinked into `~/.config`). The Nix files (`flake.nix`, `home.nix`, `hosts/`, `modules/`, `system/`, `lib/`) are an **old setup**, kept for reference. `install.sh` is the Arch bootstrap.
- UI font: Paper Mono. Icon font: **Font Awesome 7 Pro Sharp (Regular)** plus Font Awesome Brands (system package) for brand logos.
- Hyprland dispatch: `hyprctl dispatch "hl.dsp.focus({workspace=N})"`; window focus `hl.dsp.focus({window="address:0x..."})`. Lua globals can be called with an IIFE: `hyprctl dispatch '(function() if pip_bar_changed then pip_bar_changed() end return hl.dsp.exec_cmd("true") end)()'`. Lua monitor objects expose name/serial/description but **not** model.

## Theme system (`config/theme`)

- **One place to edit:** `theme.toml` (+ `templates/`). Never hard-code colours in an individual app config.
- `theme.py apply <img>` extracts a palette from the wallpaper (own extractor — wallust/matugen were tried and average away small saturated accents), renders templates, and live-reloads: kitty, ghostty, alacritty, nvim (RPC sockets), zellij, herdr, hyprland/hyprlock/hyprpaper, quickshell, GTK css, KDE/qt6ct palette, hue-rotated Adwaita icons (`Wall-Adwaita`), Brave seed-colour theme.
- `python3 -I config/theme/selftest.py` must pass after touching the extractor; it has to work for any wallpaper.
- Known limits: GTK4/libadwaita (Nautilus) cannot restyle open windows; Brave only picks up the theme while closed (shim `~/.local/bin/brave`); Dolphin is low priority.
- Qt apps: `QT_QPA_PLATFORMTHEME=kde` (set in `hyprland/env.lua`), style Fusion. Brave/Chromium dialogs use the generated GTK theme `Wall` via `GTK_THEME`, and portal FileChooser = `xdg-desktop-portal-gnome` (Nautilus-style).
- Wallpapers: `~/Pictures/wallpapers`. The Quickshell wallpaper picker is the Settings → Wallpaper & theme page, `SUPER+T` (`qs ipc call picker toggle`).
- Layout defaults in `theme.toml [settings]`: `rounding` 0, `gap` 0, `border_size` 2, `bar_floating` false, `smart_gaps` true, plus `bar_border` and `bar_opacity`, written to `out/palette.json` as real numbers/booleans (`bar_gap`/`bar_radius` were removed, the bar margin/radius are derived; theme.py's fallback for `rounding` is now 0, was 10). These drive **Quickshell only**: `out/palette.lua` still carries just `wallpaper`, `rounding` and colours, and Hyprland's values stay hand-written in `hypr/hyprland/` (keep the two in sync if you change a default). User overrides do not live here: see Appearance below.
- Details: `config/theme/README.md`.

## Appearance (radius, gaps, floating bar)

Settings → Appearance changes the corner radius, window gaps, window border, docked/floating bar and smart gaps (globally and per monitor), in Hyprland AND Quickshell, live. Built 2026-10-18; per-monitor smart gaps added the same day.

**Data model.** User overrides live in `${XDG_STATE_HOME:-~/.local/state}/quickshell/appearance.json`, e.g. `{"version":1,"radius":12,"gap":10,"edgeGap":10,"border":2,"barFloating":true,"smartGaps":true,"smartMonitors":{"Dell Inc. DELL U2515H 9X2VY5AK1D5L":false}}`. A missing key means "theme default"; `{}` or no file means all defaults. Keys and clamps (applied by both the QML writer and the Lua reader): `radius` 0–32, `gap` 0–32, `edgeGap` 0–40 (optional; unset = `gap`), `border` 0–6, `barFloating` bool, `smartGaps` bool (the default for every monitor without its own entry), `smartMonitors` = per-monitor smart gaps `{"<monitor key>": bool}` (see **Per-monitor smart gaps** below; max 16 entries, keys 1–96 printable ASCII characters without `"` and `\`, values true/false only; any invalid entry voids the whole map, the other keys still apply; an empty map is "not set"). The biggest valid file is about 1.8 KB, so the 4 KiB cap stays. The page sliders cover less: radius 0–24, gap 0–32 in steps of 2, edge gap 0–40, border 0–4. Numbers are rounded. Non-numbers, NaN, a non-object, files over 4 KiB, directories and FIFOs all fall back to defaults. Precedence: Quickshell **appearance.json > `theme.toml [settings]` (via `out/palette.json`) > built-in fallbacks**; Hyprland **appearance.json > the hand-written config**, so the page's "(default)" labels show Quickshell's defaults (today both are 0/0/2/0). The fallbacks equal the look before this feature: radius 0, gap 0, border 2, docked, smart gaps on. Derived values: `gaps_in = round(gap/2)` (the visible gap between windows is about G) and `gaps_out = edgeGap ?? gap`. Env overrides for tests:
- `QS_APPEARANCE_FILE`: the state file path, QML side.
- `APPEARANCE_FILE`: the state file path, Lua side (`managed.lua`).
- `QS_HYPRCTL`: the hyprctl binary the shell calls.

**Who reads and writes.**
- **Only writer:** the `Appearance.qml` singleton. It applies a change in memory at once, then saves after a 400 ms debounce (FileView `setText`, `mkdir -p` first). 250 ms after each save it pokes Hyprland with `Quickshell.execDetached([hyprctl, "eval", "if layout_apply then layout_apply() end"])` (array form, no shell). If `smartGaps` or `smartMonitors` changed since the last poke, it runs `hyprctl reload config-only` instead (kept from the global toggle: `set_enabled` alone is not verified to re-evaluate window rules of open windows). When the set of screens changes while `smartMonitors` is set, it also runs the `eval` once (1.5 s later), as a safety net for hot-plug.
- **Hand edits:** the FileView watcher picks them up and pokes Hyprland the same way.
- **At start or hot reload:** the shell makes no hyprctl call, because Hyprland reads the same file itself.
- **theme.py** never touches the file, so overrides survive a wallpaper apply and its `hyprctl reload`.

**Hyprland side (high level).** Hyprland reads the same `appearance.json` at every config load and applies, on top of the hand-written values, `gaps_in`/`gaps_out`, `border_size` and `decoration.rounding`. It also switches the smart-gaps rules (a lone tiled window gets no gaps, border or rounding; per monitor) and keeps the pinned PiP box gaps_out away from the screen edges and the bar (see **Pinned video box and gaps** below). At runtime the shell pokes it after each save, see above. Everything there has to be `pcall`ed and clamped, because a Lua error at config load disables the rest of the config, keybinds included.

**Hyprland managed file (`hypr/hyprland/managed.lua`).** Everything Settings → Appearance does in Hyprland lives in this one file, so the feature never edits hand-written config and vice versa.
- **Loading:** one line in `hyprland.lua`, `pcall(require, "hyprland.managed")`, after `permissions` and before the scripts. `scripts/pip-reserve.lua` requires it again (cached; the module sets `package.loaded` first, so a half-way failure is not re-run and no rule is registered twice).
- **Overrides:** reads `appearance.json` (`M.read_small_file`: `r+` open so a FIFO can't block the compositor, 4 KiB cap; pattern parser, no JSON lib) and writes ONLY the keys that are set (`hl.config` per option, each `pcall`ed): `radius` → `decoration.rounding`, `gap` → `gaps_in = round(gap/2)` and `gaps_out` (unless `edgeGap`), `edgeGap` → `gaps_out`, `border` → `general.border_size`. A missing key leaves the hand-written value alone.
- **Baseline and reset:** at load, before applying, it reads the four options back with `hl.get_config` (gaps come back as `{top,right,bottom,left}` and are normalized to an integer when equal) into `M.baseline`. `layout_apply()` writes the baseline back for keys it overrode earlier that are no longer set (Reset writes `{}`). If `get_config` fails for a key, a reset leaves the current value; a reload restores it.
- **Smart gaps:** two layers of lone-window rules, all always registered and flipped with `set_enabled` (never re-registered at runtime, so no duplicates). The gaps rules only matter while gaps are non-zero. If managed.lua is missing or broken there are no smart rules (lone windows get border 2).
  - **Catch-all** (the rules from before, `M.smart_rules`): workspace rules `w[tv1]` and `f[1]` (gaps 0) and window rules `no-border-single-wtv1` / `no-border-single-f1` (border 0, rounding 0). Enabled while `smartGaps ~= false` AND no `smartMonitors` entry is `false` (`M.catch_all_on`). It covers monitors that have no rules of their own yet.
  - **Per monitor** (`M.smart_sets`, one set per connected monitor): workspace rules `m[desc:<description>]w[tv1]` and `m[desc:<description>]f[1]` (gaps 0) and window rules `no-border-single-wtv1-m<n>-<slug>` / `no-border-single-f1-m<n>-<slug>` matching the same selectors (border 0, rounding 0). Enabled per `M.smart_for(s, key)` = the monitor's entry, else `smartGaps`, else true. `f[1]` is scoped per monitor too. A set whose monitor is gone is switched off.
  - **Selector:** `m[desc:<description>]`, except when that would not select exactly this monitor: Hyprland's `desc:` is a prefix match that returns the first monitor found, so identical monitors (same description, e.g. no serial), a description that is a prefix of another connected one, or a description with `[`/`]` or edge spaces get the connector-name selector `m[DP-5]...` (computed at registration from the monitors connected then; the key stays the description). `window_rule match.workspace` accepting `m[...]w[tv1]` is inferred from the 0.56.2 headers (WorkspaceMatchEngine uses the same static workspace selector as workspace rules), not verified live.
  - **Hot-plug:** `hl.on("monitor.added" | "monitor.removed" | "hyprland.start")` → `M.on_monitors_changed()` = `M.apply_smart(M.read())`, which registers sets for new monitors and sets every rule's state; `layout_apply()` does the same. The `hyprland.start` hook matters if the config loads before the outputs exist at Hyprland start. Subscriptions of an earlier load are removed first (global `__managed_smart_subs`), in case a reload keeps the Lua state. At most 32 sets per config generation (`M.SMART_SETS_MAX`); a reload starts over.
- **Runtime API:** global `layout_apply()` (re-read + apply + `pip_bar_changed()`, never raises, returns ok, err); module `M.parse/read/targets/effective/get/edge_margins/apply/apply_options/apply_smart/smart_for/smart_enabled/catch_all_on/monitor_key/monitor_selector/valid_key/on_monitors_changed/set_smart/capture_baseline/state_path/read_small_file`, `M.smart_rules`, `M.smart_sets`, `M.BAR_HEIGHT` 40, `M.BAR_GAP_DEFAULT` 0, `M.MAX_BYTES` 4096, `M.SMART_KEY_MAX` 96, `M.SMART_MAP_MAX` 16, `M.SMART_SETS_MAX` 32, `M.EDGE_MARGIN_MAX` 200. `M.parse` cuts nested objects out before reading the top-level keys, so a monitor named like a key (`"radius"`) inside the map never counts as one. pip-reserve uses `managed.get().barReserve` (bar height + floating gap; fallback 40) for its bottom offset and `managed.edge_margins()` for the gaps and `managed.smart_enabled(mon)` (is smart gaps in force for that monitor; re-reads the file, never raises, false on failure) for the single-window case, and refits when the resulting box changes.
- **Untouched:** `settings.lua` and `theme.lua` are the user's hand-written values (identical to before); `workspaces.lua` / `rules.lua` only lost the moved rules; `theme.py`'s `palette.lua` output is back to wallpaper + rounding + colours.
- **Reload pitfalls:** Hyprland auto-reloads the Lua config when a file is saved, so every file must load on its own. managed.lua must stay after the hand-written modules (its baseline is whatever they set). Runtime `hl.config` changes are lost on reload, but managed.lua re-applies the file at every load. Assumed, not verified live: a reload resets options to their defaults before re-running the config (either way the hand-written files set all four options explicitly).

**Pinned video box and gaps** (`scripts/pip-reserve.lua`, battlestation; added 2026-10-18).
- **Rule:** the pinned PiP/mpv/Twitch box keeps the same distance as tiled windows (margin `m` below; but see **Smart gaps** further down: `m` is 0 while "No gaps for a single window" applies on the monitor): gaps_out from the right screen edge and from the bar (bottom bar: from the bar reserve, i.e. `barReserve` = 40 docked / 40 + gapOut floating; top bar or no bar: from the bottom screen edge). The reserved right strip stays `BOX.w` = 1588 wide; the box's left edge is the strip boundary, where the tiled layout adds its own gaps_out, so tiled windows end gaps_out before it too. The video shrinks by the margin and stays 16:9: `w = 1588 - m - 2*b`, `h = floor(893*w/1588 + 0.5)`, `x = mon.x + mon.width - m - b - w`, `y = mon.y + mon.height - bottomOffset - m - b - h`. Gap 0 gives exactly the old 1588x893 at the old place.
- **Margin `m`:** `managed.edge_margins()` = effective gaps_out per side: the override (edgeGap, else gap), else the hand-written gaps_out read at load (`M.baseline`, integer or per-side table), else 0; clamped 0..200. Without managed.lua, or if it raises or returns garbage, all margins are 0 (old behaviour).
- **Border `b`:** Hyprland draws borders OUTSIDE a window's `at`/`size` for tiled and floating windows alike (a tiled window at gaps_out 10 / border 4 reports `at` 14, checked read-only with `hyprctl clients -j`), so the visible edge is `at - border`. Pinned windows have border 0 from the `pinned` rule in `rules.lua` (`hyprctl getprop <pinned window> border_size` = 0), so `PIN_BORDER = 0` in pip-reserve; change both together.
- **Who places it:** the static `rules.lua` rules (cb-pip, cb-mpv, twitch-player: `move (monitor_w-1588) (monitor_h-933)`, size 1588 893) are unchanged and still assume a docked bottom bar without gaps; pip-reserve corrects the box on `window.open` (PiP, mpv), on the first `window.title` of a pinned video window (the Twitch player has no title at open; only when margins are non-zero, so gap 0 behaves exactly as before), on heal, and in `refit()` whenever the box (bar offset, margins, size) changes. `layout_apply()` → `pip_bar_changed()` → refit, so a gap change in Settings moves open pinned windows at once. A window placed once is not snapped back by later title changes.
- **Smart gaps ("No gaps for a single window"):** the effective margin `m` is 0 on both sides (right edge and bar) while Hyprland gives the lone tiled window beside the box no gaps. That is the case when (a) `managed.smart_enabled(mon)` is true for the video's monitor (the monitor's rule set: its `smartMonitors` entry, else `smartGaps`, else on; a monitor without a rule set follows the catch-all rules, `catch_all_on`; any failure = false) and (b) the monitor's active workspace has exactly one visible tiled window, the same thing the `w[tv1]` rule counts: floating and pinned windows (the video itself included), hidden and unmapped windows do not count, other monitors and workspaces neither; or it holds a maximized window (`fullscreen == 1`, the `f[1]` rule; real fullscreen is `f[0]`, does not match, keeps the gaps). Otherwise `m` = `gapsOut` as before. With `m` 0 the box is the old flush 1588x893 box. **Rounding:** on the battlestation the pinned windows had NO rounding rule (only the workstation's cw-pip/twitch rules have `rounding = 0`), so they got the normal `decoration.rounding` (12 with the radius override; `hyprctl getprop address:<a> rounding` = 12 measured). While `smart_gaps_apply` holds, `pip-reserve.lua` enables three window rules `pip-smart-rounding-1..3` (`rounding = 0`, matching `pin = true` + the PiP title / mpv initial_class / org.quickshell class), registered once disabled and flipped with `set_enabled` in `sync()` (`sync_rounding`); otherwise rounding stays the normal value. Verified live after `hyprctl reload`: smart on (one tiled window on workspace 7) -> getprop rounding 0 for both pinned windows, configerrors empty. Not verified: the off state (second tiled window) and that a live `set_enabled` flip re-evaluates already-open windows (assumed; if not, rounding only updates on the next window rule evaluation). Workstation unchanged (its rules already force 0). The reserved strip stays 1588 wide. `pip-reserve.lua` does the counting (`smart_gaps_apply`) and refits on `window.open/close/kill/destroy/move_to_workspace/pin/fullscreen/update_rules`, `workspace.active/move_to_monitor/removed` and `layout_apply()` (setting changes); the refit only moves the box when its computed place changes, so moving a floating window or repeated events never loop. A closing window that is still listed during its own close event is left out of the count. Unknown event names are skipped (`pcall`). **Hyprland Lua API objects are userdata** (monitors, workspaces, windows: `type(x)` is `"userdata"`; probed live with a read-only `hyprctl eval` writing to a scratch file): test them with nil checks (`ws == nil`, `w.workspace ~= nil`), never `type(x) == "table"`; their fields are plain values (`floating/pinned/mapped/hidden` booleans, `fullscreen` a number, 0 for normal windows, `workspace.id` a number, `address` a string, `at/size` tables; `hl.get_windows()/get_monitors()` return real tables), and stub tests must model that (the harness hands proxies and overrides `type`). Still only confirmable live: `fullscreen == 1` for a maximized window (assumed from `hyprctl clients -j`) and that `window.fullscreen` / `window.update_rules` fire on fullscreen and float toggles.
- **No stacking:** every pinned video window goes into the same single box (they overlap); there is no multi-box layout.
- **Hooks:** pip-reserve's `hl.on` subscriptions are kept in the global `__pip_reserve_subs` and removed at the next load, so a reload that keeps the Lua state does not double them.
- **Not changed:** `pip-orientation.lua` (workstation only, its own fixed geometry), the Steam OSK rule (pinned, flush bottom center on purpose), the Twitch popout chat rule (not pinned), `switch-workspace.lua` (restores a window's own previous geometry).

**Per-monitor smart gaps.**
- **Monitor key:** the monitor description exactly as Hyprland reports it (`hyprctl monitors -j` `.description` = Lua `hl.get_monitors()[i].description` = Quickshell `Hyprland.monitorFor(screen).description`; e.g. `Microstep MPG271QX OLED 0x01010101`, `Dell Inc. DELL U2515H 9X2VY5AK1D5L`, checked read-only 2026-10-18). It is make + model + serial, so it survives reboots and port changes (connector names DP-1/DP-3 do not). Fallback when the description is not a valid key (non-ASCII, `"`, `\`, empty, > 96): the connector name (not stable; both sides use the same rule, `Appearance.monitorKey()` / `M.monitor_key()`). Not `model|serial` as in `bars.json`: Lua monitors have no `model` field, and the description is what the `desc:` selector needs.
- **Edge cases:** identical monitors without a serial share one key (one setting for both; the rules use connector selectors so both are matched). A monitor that is not connected keeps its entry (and while it is `false`, the catch-all stays off; the connected monitors have their own sets). Entries are never pruned automatically; Reset or the all-monitors switch clears them.
- **Limitations:** a monitor connected later is covered by the catch-all until its set exists; if neither the `monitor.added` event nor a later `layout_apply()`/reload registers it, and an explicit `false` exists, it has no smart rules (gaps/border like a normal window). The QML parser decodes JSON escapes (`\u0041` → `A`) while managed.lua rejects any backslash in the map, so a hand-written escaped key is ignored by Hyprland only; Quickshell never writes escapes (valid keys need none).

**Theme.qml API** (effective value = override, else palette default):
- **Mirrors:** `radius` (R, for outer elements), `rounding` (old alias of `radius`), `gap`, `gapIn`, `gapOut`, `borderSize`, `barFloating`, `smartGaps`.
- **Bar:** `barGap` (= floating ? gapOut : 0), `barRadius` (= floating ? R : 0), `barPad` 6, `barReserve` (= barHeight + barGap).
- **Popups:** `popupGap` (floating: max(4, gapOut); docked: 8) and `edgeGap` (floating: gapOut; docked: 12).
- **Concentric rule:** `inner(outer, inset) = outer <= 0 ? 0 : max(min(outer, 4), outer - inset)`. It returns exactly 0 at R = 0, and never goes below 4 px (or R, if R is smaller) otherwise.
- **Named radii:** `radiusChip = inner(R, 6)` (bar chips), `radiusItem = inner(R, 12)` (items in a popup card), `radiusPage = inner(R, 18)` (Settings page boxes), `radiusDeep = inner(radiusItem, 8)`, `radiusModal = inner(R, 20)` (formerly RecordMenu rows, now unused).
- **Pills stay pills:** toggles, slider tracks, dots and progress bars keep `min(h/2, …)` shapes; only where R comes from changed.
- **Slider handle:** `Slider.qml` thumb is always square (16x16, width == height), radius `min(8, Theme.radius)`: square at R=0, full circle once R >= 8; it travels `x = value * (width - 16)`, row height unchanged (24).
- **Masks:** `clip: true` clips to the bounding box, not the rounded shape. Media art and wallpaper thumbnails therefore use a MultiEffect mask when the radius is > 0. The HaStrip/HaVacuum segment ends use per-corner radii (Qt 6.12).
- **Palette read:** the first palette read is synchronous (`blockLoading`), so the first frame already has the right shape.

**`Btn`.** Two properties set the corner: `outerRadius` (default `Theme.radius`) and `inset` (default 12). The radius is `min(Theme.inner(outerRadius, inset), floor(height/3))`, so a small button never turns into a pill at a large R. A caller that is not directly inside a popup card sets both:
- Btn `outerRadius: Theme.radiusModal; inset: 8` was RecordMenu's segment style (menu removed 2026-10-20).
- Settings close button and page-level buttons on the Bar/Appearance pages: `inset: 18`.
- Monitor-card Top/Bottom: `outerRadius: Theme.radiusPage; inset: 9`.
- Chip eye buttons (`Mb`): `outerRadius: inner(radiusPage, 8); inset: 6`.
- Nested buttons in NetPanel, HaPanel, HaEntity and HaVacuum.

NotifCard action buttons follow the same rule. The NotifCard and CalPanel accent stripes run from `y = radius` to `height - radius`, so they stay on the straight edge.

**Docked vs floating geometry.**
- **Docked:** margins 0, radius 0, reserve = barHeight. This is today's look and pixel-identical to the committed shell.
- **Floating:** the bar sits `gapOut` from the screen edge and from both sides, with radius R. The reserve (`BarReserve` exclusiveZone) is barHeight + gapOut, so the gap between bar and windows is gapOut.
- **Popups:**
  - The card sits `barReserve + popupGap` from the bar edge, and `edgeGap` from the side when floating (docked: 8).
  - Placement is chip-centred (2026-10-18, see "Popups centred on their chip" below); `Popups.right` no longer exists.

- **Toasts, OSD and tray menu:**
  - Toasts: top = `edgeGap + barReserve` with a top bar.
  - OSD: bottom = `70 + barReserve` with a bottom bar.
  - TrayMenu: `popupGap` away from a floating bar, flush when docked.

## Popup motion (`PopupHost.qml`, tokens in `Theme.qml`)

- **Spec** (Theme tokens): open `popupOpenMs` 180 OutCubic (fade + scale 0.96->1 from the bar side/chip x + 10 px slide), close `popupCloseMs` 120 InCubic, chip switch `popupMoveMs` 240 OutCubic for card x/width/height, content fade-out `popupFadeOutMs` 70 then fade-in `popupFadeInMs` 160.
- **How it works:** `t` = open progress (Behavior, interrupt-safe retarget). `content`/`center` are the *displayed* popup and chip centre; `Popups.name`/`center` are the request. `sync()` handles cold open (load content, 40 ms for the layer surface to map, then t=1), switch (fade out, swap content+center, fade in; `morphing` true for ~300 ms so Behaviors on x/width/height glide), same-popup re-request while closing (resume). x is computed from the TARGET width so x and width animate together; y hangs off the bar edge so the card grows away from it. Content is a Loader at the target size inside an Item sized to the animating card (clipped only while morphing), so panels don't re-layout per frame. Behaviors are off outside `morphing`, so panels that animate their own height (CenterPanel collapse) are not smoothed twice. `layer.enabled` only during open/close (no text-over-background double blend).
- **Jitter root causes (before):** x/y jumped on switch (no animation at all); card height flashed to a wrong size for 2 frames after the content swap (loader had no item / panel settling); 28 px slide + 150 ms OutCubic = only ~6 visible frames; opacity applied per child; content width followed nothing but was swapped mid-fade.
- **Verified** (backdrop rig: a temporary solid-green layer window + wf-recorder on DP-3, card bbox/alpha per frame; rig removed afterwards): max per-frame x step 956 px -> 222 px (smooth OutCubic curve, ~14 frames per switch); open/close monotonic alpha; rapid A->B->C and mid-flight reversal retarget with no snap; same-chip toggle closes. Clamped (right-edge) and centred chips both tested via `qs ipc call popup toggle <name>`.
- **Not verified:** real mouse click path (only IPC driven; clicks use the same `Popups.toggle`), Esc, click-outside.
- **Test:** open one popup, then `qs ipc call popup toggle media` / `net` / `cal` in turn: the card should glide and cross-fade; same name again closes.
