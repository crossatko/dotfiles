# AGENTS.md — dotfiles handbook for AI agents

Read this first. It describes the machines, the repo, the conventions and the current state of the config, so you can continue without re-deriving it. It is a state document, not a changelog (history lives in `git log`); the user's own apps document themselves in their repos (see "Own apps").

## Working rules (mandatory)

### 0. Public repo: never write real setup details

This repo is **public on GitHub**. Never write anything identifying the user's real setup into it: in code, comments, docs, tests, notes, commit messages or screenshots. That means:
- no real hostnames / server or machine names, Tailscale or tailnet names (`*.ts.net`, MagicDNS short names); <!-- privacy-ok -->
- no real URLs or IP addresses (LAN/RFC1918, Tailscale `100.64.0.0/10`), MAC addresses, device serials (monitor descriptions with serials, Bluetooth addresses); <!-- privacy-ok -->
- no usernames, accounts or emails (the user's or anyone's), tokens or keys, personal channel / server / library / calendar names.

Use placeholders instead: `jellyfin.example`, `example-host`, `192.0.2.10`, `user@example.com`, `<token>`. Real values live outside the repo (`~/.config/<tool>/...`, `~/.local/state/...`) or in git-ignored files (`config/hypr/.secrets`). Notes for future agents describe mechanisms, not the user's values. Agents may mention real values to the user in chat, never in repo files.
Enforced by `.githooks/pre-commit` (`git config core.hooksPath .githooks`, set by `install.sh`): it blocks staged lines matching generic patterns plus a private deny-list at `~/.config/dotfiles-private/denylist` (outside the repo). A line containing `privacy-ok` is skipped; `--no-verify` only on the user's explicit decision.

### 1. Global rules

Subagent delegation, change documentation (notes = current state + short caveats, each app documents itself) and the no-attribution rule live in the global `~/dotfiles/CLAUDE.md` (symlinked to `~/.claude*`). They apply here too; they are not repeated in this file.

### 2. Safety rules learned the hard way (repo-specific)

- **Kill Quickshell only by exact PID.** The user's shell is the bare `/usr/bin/quickshell` process. `pgrep -x quickshell` also matches other instances (the Twitch app, probes); `kill`ing by name or relaunching blindly creates duplicates.
- **Don't edit a popup's QML file while that popup is open.** Hot reload crashed Qt's Repeater (segfault) twice. Test in an isolated instance (`quickshell -n -p <dir>`) or with the popup closed.
- Hot reload only works for files already loaded. A new QML type needs a `qmldir` entry AND a full quickshell restart: the running shell does not re-read `qmldir` on hot reload ("X is not a type"; settings pages load lazily, so it only shows when the page opens). Restart: kill the exact quickshell PID, then `hyprctl eval 'hl.exec_cmd("env QSG_USE_SIMPLE_ANIMATION_DRIVER=1 quickshell")'` (`hyprctl dispatch exec` silently does nothing with the Lua config). Changed `.frag`/`.qsb` shaders are not hot-reloaded either. A failed reload keeps the old generation running.
- Don't touch the screen-sharing portal routing (`config/xdg-desktop-portal`). ScreenCast/RemoteDesktop/Screenshot must stay on the Hyprland portal.
- **Secrets:** `config/hypr/.secrets` (`OPENROUTER_API_KEY`, `HA_TV_WEBHOOK_URL`, `HA_GAMESCOPE_WEBHOOK_URL`, Home Assistant `HA_URL`, `HA_TOKEN`, optional `HA_URL_FALLBACK`) is git-ignored; placeholders live in the tracked `config/hypr/.secrets.example`. Never print, log or commit values. WiVRn pairing data is also not tracked.
- **Licensed fonts stay out of the repo.** The full Font Awesome 7 Pro desktop set (Classic, Sharp, Duotone, Sharp Duotone; Brands comes from the system package) is installed in `~/.local/share/fonts/FontAwesomePro/` only.
- Screenshot tips: `grim -g "x,y WxH"`; Hyprland dims unfocused windows (focus first when sampling colours); popups open on the *focused* monitor. The user switches workspaces under you: capture only after checking the active workspace and that no foreign window overlaps.
- Never run `theme.py` from a scratch copy with the real `HOME` (it rewrites links in `~/.config` and `~/.local/share/themes`); set `HOME` in the same command.

## The machines (Linux)

- Arch-based (CachyOS), **Hyprland 0.56 with the native Lua config** (`hl.*`, not a plugin), Quickshell 0.3.2 (QML) for bar/launcher/notifications, hyprpaper, hyprlock.
- **Battlestation** (primary desktop): two 2560x1440 monitors (a 360 Hz OLED main one and a 60 Hz one; the bar lives on the 60 Hz one, below/above depending on layout), RX 9070 XT, runs the user's **Hyprland fork** (glass compositing; see "Own apps"). **Workstation** (work machine): stock Arch `hyprland` 0.56.2, ultrawide 3440x1440 plus a second monitor, RX 5700, no AV1 hardware. Per-host differences live in `config/hypr/hyprland/host.lua` (`$HOSTNAME` is read first, so tests override the host with it) and `hosts/<Host>/`.
- Only `~/dotfiles/config` is live (symlinked into `~/.config`). The Nix files (`flake.nix`, `home.nix`, `hosts/`, `modules/`, `lib/`) are an **old setup**, kept for reference. `install.sh` is the Arch bootstrap (packages, symlinks, hooks); `system/etc/` holds root-owned files the user copies by hand (the agent has no sudo).
- UI font: Paper Mono. Icon font: **Font Awesome 7 Pro Sharp (Regular)** plus Font Awesome Brands (system package) for brand logos.
- Hyprland dispatch: `hyprctl dispatch "hl.dsp.focus({workspace=N})"`; window focus `hl.dsp.focus({window="address:0x..."})`; monitor focus `hl.dsp.focus({ monitor = "DP-3" })`. `hyprctl keyword` is refused with the Lua config. Lua globals can be called with an IIFE: `hyprctl dispatch '(function() if pip_bar_changed then pip_bar_changed() end return hl.dsp.exec_cmd("true") end)()'`. Lua monitor objects expose name/serial/description but **not** model. Hyprland Lua objects (monitors, workspaces, windows) are userdata: test with nil checks, never `type(x) == "table"`. `hl.dsp.window.pin({action=true})` TOGGLES. `Hyprland --verify-config` dumps core, so there is no CLI config check; use `hyprctl configerrors` after a reload.
- `xdg-mime default org.gnome.Nautilus.desktop inode/directory` is set in the untracked `~/.config/mimeapps.list` (otherwise folders open in a terminal); a new machine needs it.
- Dangling `~/.config/{swaync,waybar}` symlinks from old installs can be deleted by hand (Quickshell replaced waybar, swaync, tofi).

## How to test (all features, described once)

- **Isolated shell:** copy `config/quickshell` to a short dir (or start from `git archive HEAD config/quickshell` and copy changed files over it to rehearse hot reload), make a test `HOME` (`.config/theme` and `.local/share/fonts` symlinked, copies of `.local/state/quickshell/*.json`) plus `XDG_{CONFIG,STATE,CACHE,DATA}_HOME` inside it, a short `XDG_RUNTIME_DIR` with `hypr`/`wayland-1` symlinks to the live one, and run `dbus-run-session --config-file=<conf without <servicedir>>  quickshell -n -p <dir>`. Drive it with `quickshell ipc --pid <pid> call ...`; temporary test-only `IpcHandler`s go in the copy only. Env hooks for the state files: `QS_APPEARANCE_FILE`, `QS_ANIM_FILE`, `QS_WALLPAPERS_FILE`, `QS_HYPRCTL` (stub binary), `QS_HA_SECRETS`/`QS_HA_STATE_DIR`, `QS_AI_*`, `QS_TAILSCALE`/`QS_MULLVAD`, `QS_LAUNCHER_NET_FIXTURE`, `QS_WEBAPP_HELPER`, `QS_QUICKGET`, `SCREENREC_*`, `SHOT_*`. A scratch launcher/modal must not take focus (`ModalMenu` grabs exclusive keyboard focus): set `keyboardFocus: None` and an empty mask in the copy. Kill by exact PID, then orphaned poller shells (ppid 1) of the test HOME.
- **Nested compositor** (anything about glass, scale, layers, window rules, wallpapers, GTK/Qt apps): start `Hyprland -c <config copy>` with its own short `XDG_RUNTIME_DIR` (socket paths must be short; `WAYLAND_DISPLAY` absolute if needed), hidden via `hl.dsp.exec_cmd(cmd, {workspace="special:x silent", no_initial_focus=true})` or floated on a monitor, add outputs with `hyprctl output create headless TEST` + `hl.monitor({output='TEST', mode='WxH@60', scale=s})` + `hyprctl reload`. Export the nested `XDG_RUNTIME_DIR` / `HYPRLAND_INSTANCE_SIGNATURE` / `WAYLAND_DISPLAY` (never `ls -t` for the signature; the user may run other nested instances), capture with `grim -o TEST` on the nested socket, and put a solid/checkerboard backdrop window or layer behind translucent things. Headless outputs only render while the nested window is visible. Use `/usr/bin/Hyprland` for stock behaviour, `/usr/local/bin/Hyprland` for the fork. `bars.json` in the test HOME must enable `TEST` (headless outputs have no model, key = name).
- **Never inject synthetic input into the live session.** Real clicks/drags/keys are "not verified" unless the user does them; the nested instance may be driven with `hl.dsp.send_shortcut`, `hl.dsp.cursor.move` or a virtual-pointer client that refuses any socket but the nested one.
- **Unit-level:** `python3 -I config/theme/selftest.py` (extractor, must pass for any wallpaper), `python3 -I -m unittest discover -s config/url-router/tests`, `... -s config/launcher/jellyfin/tests`, `... -s config/quickshell/bin/tests` (webapp helper), `luac5.5 -p` on Lua files, `qmllint` (the one on PATH is Qt5: use `cd config/quickshell && /usr/lib/qt6/bin/qmllint -I /usr/lib/qt6/qml $(find . -name '*.qml')`; current state: 7 warnings, all the `Type X not declared as singleton in qmldir` false positive for Theme/Binds/Brightness/BarWidgets/HomeAssistant/Popups/VpnSwitch; remaining qmltypes gaps (opaque `UntypedObjectModel.values`, `BluetoothAdapter`, `PopupAnchor`, `PanelWindow` uncreatable, duck-typed page hooks) are suppressed with a trailing `// qmllint disable <category>` on that line; do not disable `import` globally, it hides missing modules), `qmltestrunner` (offscreen) for pure QML logic (test files kept outside the repo).
- **Measuring bar/chip alignment:** temporary `console.log` of `mapToItem(null,0,0)` + size, `grim -g` crops, per-chip background interpolation; judge on fractional-edge margins, not bbox.

## Theme system (`config/theme`)

- **One place to edit:** `theme.toml` (+ `templates/`). Never hard-code colours in an app config. Details: `config/theme/README.md`.
- **The theme is per machine; a wallpaper switch changes no tracked file.** Tracked: `theme.toml` (settings, `wallpaper` = the default) and `default/` (a generated neutral wallpaper + the outputs rendered from it, regenerate with `theme.py default`, home-independent `~/` paths). Git-ignored: `theme.local.toml` (this machine's `wallpaper`, written by `apply` / the picker; optional local `[settings]`, `[overrides]`, `[vars]` `tv_wallpaper` / `static_blocks`, merged over `theme.toml`) and `out/` (this machine's render, what every app reads). `bin/theme-seed` (POSIX sh; install.sh, `theme.py`, the git hooks) fills a missing `out/` from `default/` (leading `~/` expanded) and writes `out/.default`, but **only on a machine without `theme.local.toml`** (fresh clone, the Mac); a machine with a selection whose `out/` is missing, incomplete or only the seeded default gets `theme.py render` from the hooks instead (`THEME_SEED_FORCE=1` seeds anyway; the hook does that only if that render failed). `out/` vanishes on such a machine when a rebase / merge replays the untracking commit or when switching back from an old commit that still tracked it, so the hooks (`post-merge`, `post-rewrite`, `post-checkout`) all repair it; `render` and the seeder never reload an app. Note `steam-tv-dim.lua` / `steam-streaming.lua` re-apply `palette.lua`'s `wallpaper` to hyprpaper on TV resyncs, so whatever `out/palette.lua` says reaches the screen then; while that marker exists `out/` follows `default/` changes, `theme.py render/apply` drops it and from then on `out/` is only ever written by the render. Fatal consumers have fallbacks: Hyprland `theme.lua` and nvim `pcall(dofile, out/palette.lua)` then `default/palette.lua`, ghostty uses `config-file = ?...`. herdr has no include: `deploy()` writes `~/.config/herdr/config.toml` as a generated file (tracked `config/herdr/config.toml`, which carries the default `[theme]` block and is only touched by `theme.py default`, plus this machine's block); a herdr settings edit needs `theme.py render`. Tested behaviour of a missing `out/` file: kitty ignores the include, ghostty (`?`) is silent, alacritty skips a missing import (checked with `alacritty migrate --dry-run`, not at runtime), zellij's `wall.kdl` (tracked symlink into `out/`) dangles and `zellij setup --check` reports it, hyprlock/hyprtoolkit/hyprpaper need the seeded file.
- `theme.py apply <img>` extracts a palette from the wallpaper (own extractor: wallust/matugen average away small saturated accents), renders templates to `out/`, and live-reloads kitty, ghostty, alacritty, nvim (RPC sockets), zellij, herdr, hyprland/hyprlock/hyprpaper, quickshell, GTK CSS, KDE/qt6ct palette, hue-rotated Adwaita icons (`Wall-Adwaita`), Brave, Thunderbird. Wallpapers: `~/Pictures/wallpapers` (`wallpaper_dirs`), videos `~/Videos/wallpapers` (`video_dirs`). Picker = Settings > Wallpaper & theme, `SUPER+T` (`qs ipc call picker toggle`).
- Layout defaults in `theme.toml [settings]` (rounding, gap, border size, floating bar, smart gaps, bar border/opacity) go to `out/palette.json` and drive **Quickshell only**; `out/palette.lua` carries just `wallpaper`, `rounding` and colours, and Hyprland's own values stay hand-written in `hypr/hyprland/` (keep the two in sync when changing a default). User overrides live in `appearance.json` (see Appearance).
- **Per-host output:** GTK3/GTK4 CSS, `kvantum.kvconfig` and `brave-glass.css` are rendered into git-ignored `out/host/` because the fill alpha depends on the compositor (a fixed fill on solid_glass, `bar_opacity` on stock). A pull touching `config/theme/` (not `default/` alone, unless `out/` is still the seeded default) re-renders via `.githooks/post-merge` / `post-rewrite` -> `theme-render`, which first seeds `out/` on every OS; `post-checkout` only seeds (`THEME_RENDER_SKIP=1` skips the render). After pulling on a new host run `~/.config/theme/theme.py render` once (relinks GTK CSS; until then GTK apps use stock Adwaita). On macOS the engine never runs (`theme.py` exits 0 on darwin), only the seeding.
- **Pulling the commit that made the theme per machine (other Linux machines):** git deletes the old tracked `out/*` and refuses when they have local edits (copy `out/`, `theme.toml` and the herdr config to `~/.local/state/theme/legacy/` as `out/`, `theme.toml`, then `git checkout -- config/theme config/herdr`). `theme-render` then runs `theme.py adopt-legacy` (from that folder, else from the `ORIG_HEAD` blobs): the previous wallpaper goes into `theme.local.toml` (a path that does not exist here falls back to the default with a warning), local `[settings]`/`[overrides]` edits become local overrides, then it renders. `theme.py migrate-local` is the committing machine's one-off version (reads the working `theme.toml` and the old hyprpaper template from git HEAD).
- Qt: `QT_QPA_PLATFORMTHEME=kde` (`env.lua`), style Kvantum theme `Wall` (`theme.toml qt_style = "kvantum"`; falls back to Fusion with a message if Kvantum is missing, install `kvantum` + `kvantum-qt5`), icons `Wall-Adwaita-Qt`. Brave/Chromium dialogs use the GTK theme `Wall` via `GTK_THEME`; portal FileChooser = `xdg-desktop-portal-gnome`.
- **Light / dark mode:** `theme.py mode [get|dark|light|toggle]`, UI = Settings > Wallpaper & theme > Color mode (`SettingsWallpaper.qml`, `Theme.mode` / `Theme.light` from `palette.json`). The mode is per machine in `~/.local/state/theme/mode` (default dark); `hypr/hyprland/autostart.lua` sets the freedesktop `color-scheme` from it at login, `theme.py` keeps it on every apply; theme writes are serialised by `~/.local/state/theme/apply.lock`. Glass settings are per mode (theme.toml `[settings]` / `[settings_light]` glass keys, glass.json top-level / `light`; `managed.lua`, `GlassTuneCtl.qml`), and light mode gives a backdrop-less bar per-monitor wallpaper ink (`palette.json` `dark` / `wall_ink`, `Theme.inkOn`, `Bar.qml` `ink`). Details and limits: `config/theme/README.md` (Light / dark mode). Check after changes: `python3 -I config/theme/selftest.py` (both modes), render dark before / after and diff (must be identical apart from `mode` / `card_fill` / `plain_fill_min` in `palette.json`). Testing the UI nested needs the real `hyprctl` on PATH (a shim makes `Theme.glass` / `hypr_solid_glass()` false, so the glass-only fills and the Glass page do not show) and a light render's `palette.json` + `palette.lua` in the test HOME's `~/.config/theme/out` (then `hyprctl reload` in the nested instance so managed.lua applies the light glass set; headless test outputs are not in `wall_ink`, add them by hand); never `pkill -f` with a pattern that matches your own command line.
- Known limits: GTK4/libadwaita cannot restyle open windows; Brave only picks the theme up while closed (the `~/.local/bin/brave` shim applies it); `theme.toml` `thunderbird`/`thunderbird_radius`, `brave_mode`, `gtk_glass*`, `qt_symbolic_icons` are the knobs.
- `out/hyprpaper.conf` is generated per machine: the tracked template has only the catch-all block, this machine's per-monitor blocks (monitor descriptions with serials) live in `[vars] static_blocks` of the git-ignored `theme.local.toml` (they may use `{{wallpaper_t}}` / `{{tv_wallpaper_t}}`); `monitor_blocks` from `wallpapers.json` come last. Old commits still contain the serials (no history rewrite).
- Testing the theme engine without touching the session: temp clone + temp `HOME` with `~/.config/theme` linked to it, `THEME_OUT_DIR` for another `out/`, and shims on `PATH` for `pkill`, `hyprctl`, `gsettings`, `kwriteconfig6`, `herdr`, `hyprpaper` (`apply` reloads apps by name: never run it with the real `PATH`/`HOME` while testing); nested Hyprland for hyprpaper/hyprlock screenshots (a minimal config that requires `hyprland.theme`; the real `autostart.lua` would `pkill hyprpaper`).

### Toolkit glass (GTK4, GTK3, Qt/Kvantum, Brave, Firefox, Thunderbird)

- **Principle:** the compositor already applies tint / darkening / saturation / refraction behind any translucent window with the shell cards' values, so app CSS paints only the card fill (`Theme.cardFill` on solid_glass; `bar_opacity` on plain blur, NOT the shell's bar fill) plus per-part offsets (`theme.toml gtk_glass_{chrome,header,sidebar,view,popover,dialog,control}`, `gtk_glass_fill` overrides the base, `gtk_glass` false = opaque). Repeating tint/darkening in CSS would apply it twice. Glass slider changes reach running GTK apps live; CSS changes (palette, blur variant) need `theme.py apply` and an app restart. `theme.py hypr_solid_glass()` and `Theme.qml` use the same test: keep in sync.
- **GTK4/libadwaita:** `~/.config/gtk-4.0/gtk.css` -> `out/host/gtk4.css` (template `gtk4.css`, link set in `deploy()`), overrides libadwaita named colours with alpha. **Blur needs `backdrop-filter`:** GTK >= 4.22 creates an empty `ext-background-effect-v1` blur region and Hyprland treats that as "no blur", so a `window { backdrop-filter: blur(...) }` rule and popover rules are required. Do not also set `--*-bg-color` variables at user priority (ghostty sets `:root --window-bg-color` itself). User CSS outranks theme CSS regardless of specificity, so every state that changes a fill must be listed. Needs GTK >= 4.22; nautilus list view, Papers, Epiphany, light scheme unverified. `nautilus --new-window` attaches to a running user instance: test under `dbus-run-session`.
- **GTK3:** `~/.config/gtk-3.0/gtk.css` -> `out/host/gtk3.css`, scoped to `window.csd` (Gecko reads system colours from unrealised contexts without `.csd`, so Firefox/Thunderbird are untouched); menus stay opaque; windows without a header bar (server-side decorated, no `.csd`) stay opaque. GTK3 inlines Adwaita colours, so explicit selectors, not `@define-color`.
- **Qt:** a palette alpha alone stays opaque; Kvantum `translucent_windows` (via `write_kvantum_theme()`: KvFlat recoloured to the palette + `out/host/kvantum.kvconfig`) sets `WA_TranslucentBackground`; video apps and quickshell are `opaque=`. `~/.config/Kvantum/kvantum.kvconfig` selects `Wall`. Metrics of Qt and GTK3 copy libadwaita's measured sizes (see `kvantum_svg.py`, `templates/kvantum.kvconfig`, `templates/gtk3.css`). Kvantum quirks that cost time: push buttons add extra px over frame+text, default button label colour cannot be set, item-view margins are capped, unfocused windows request `itemview-*-inactive`. ### Wallpapers (per monitor, videos, links)

- **State:** `${XDG_STATE_HOME:-~/.local/state}/theme/wallpapers.json` (host-local, written only by `theme.py`; `THEME_WALLPAPERS_FILE` / `QS_WALLPAPERS_FILE` override): `{"version":1,"primary":"<key>","monitors":{"<key>": "<img>" | {video, mode, still, play, wind, ease}},"primary_video":{...},"links":[[a,b],...],"optimize":..,"optimize_speed":..}`. Key = monitor description as Hyprland reports it (else connector). The **primary** monitor's wallpaper is the theme source (`wallpaper` in `theme.local.toml`); `primary` unset = monitor at 0,0; a monitor without an entry shows the primary's wallpaper. Unplugged monitors' entries are kept.
- **CLI:** `theme.py apply <file> [--monitor k]... [--mode once|loop] [--play S --wind S --ease S]`, `clear k...`, `primary k`, `link a b [--from k]`, `unlink a b`, `video start|stop|restart|sync|status|thumb(s)|replay|optimize|optimize-speed|loopinfo|hwdec`. A non-primary apply only re-renders `out/hyprpaper.conf` and live-sets the output with `hyprctl hyprpaper wallpaper "<selector>,<path>,cover"`; **the selector must match the config block's** (`desc:<key>` for description keys, connector only for connector keys; a mismatch exits 0 silently, `live_set_wallpaper()` polls `listactive` and restarts hyprpaper). `templates/hyprpaper.conf` is block syntax only (hyprpaper 0.8 has no `preload=`; paths written with `~`, which hyprpaper expands) with a catch-all block, `{{static_blocks}}` (this machine's own blocks) and `{{monitor_blocks}}` (later blocks win); `tv_wallpaper` (local `[vars]`) falls back to the main wallpaper when the file is missing. hyprpaper does not hot-reload its config; a full apply restarts it.
- **Settings page** (`SettingsWallpaper.qml`, `WallpaperMonitorCard.qml`, `WallpaperTile.qml`): header = theme-source name + palette swatches; monitor cards (2+ screens) pick the edited monitor ("Follow primary" / "Make primary"); Images / Videos tabs; Videos tab has Play once / Loop, Optimize toggle + speed, "Play for" / "Wind down" / "Ease-in" sliders that apply on RELEASE (cancel + re-bake). Session memory (tab, edited monitor, mode) via the `memory` page hook. Test hooks: `qs ipc call wallpaperpage tab images|videos`, `... monitor <key>`.
- **Monitor links:** linked monitors always change together (wallpaper apply/mode/timing/follow go to the whole group; "Make primary" stays per monitor). Bars: links live in `bars.json` under reserved key `"_links"`; linked monitors share on/off, edge and layout (`BarConfig.set`/`BarWidgets.store` write every key of the group; the last-bar rule is about the group). UI: `MonitorCardRow.qml` + `MonitorLinkButton.qml`; each card gets round cut-outs around link buttons via `NotchMask.qml` + `shaders/notchmask.frag(.qsb)` (SDF stroke, spacing derived from `Theme.controlGap`). `NotchMask` is a qmldir type: live restart needed.
- **Video wallpapers** (mpvpaper 1.9 + libmpv): one `mpvpaper -l bottom -o "<opts>" <connector> <file>` per output (hyprpaper stays on `background`, so the video is always above the still and below windows), pid files + logs in `$XDG_RUNTIME_DIR/theme-video/`, stop = SIGTERM/SIGKILL only if `/proc/<pid>/comm` is `mpvpaper`, flock serialises syncs. `scripts/start-hyprpaper.sh` runs `theme.py video start` after hyprpaper; `autostart.lua` re-syncs on `monitor.added/removed`. `MPV_OPTS` carry `load-scripts=no` so `mpv-mpris` does not turn wallpapers into MPRIS players (explicit `scripts=winddown.lua` still loads). No `-p` auto-pause (unreliable on Hyprland). Players keep decoding behind windows; looping 4K60 sources are the worst case (prefer 24-30 fps or play-once).
  - **Once vs loop:** once = plays, holds the last frame (the login animation); stills (`video_still()`, ffmpeg, cached in `$XDG_CACHE_HOME/theme/video`) feed the palette and the hyprpaper image under the player. The hold point skips a black tail (`video_hold()`, blackdetect on the tail); mpv's `end=` is exclusive, so the still is the frame BEFORE t_stop. Timed play-once: `play` S then raised-cosine wind-down over `wind` S (covers wind/2 of media, `t_stop = play + wind/2`, `WIND_AVG` shared by theme.py / `mpv/winddown.lua` / QML), no `play` = full length. Runtime ramp steps through source frames (choppy), so with Optimize on a per-monitor **baked file** is built (see below). Runtime smoothing is off on high-refresh monitors (GPU cost); mpvpaper presents at the output's frame callbacks, so `display-fps-override` must equal the real refresh or playback speed scales wrongly (`winddown-fps`).
  - **Optimize for monitor (default on):** per (video, monitor) HEVC Main copy (H.264 fallback via `out_codec()`; `hevc_vaapi` / libx265; encoders and hardware decode are probed per machine and cached under `$XDG_RUNTIME_DIR/theme-video/probe-*`; `THEME_FORCE_NO_HWDEC`, `THEME_OUT_CODEC`, `THEME_FORCE_ENCODER` simulate other machines) in `$XDG_CACHE_HOME/theme/video/opt/` (LRU-capped), scaled to the monitor's physical pixels, fps = largest of 25/30/40/45/50/60 dividing the refresh. `hevc_vaapi` + `hvc1` needs `-bsf:v extract_extradata` (else undecodable). Apply plays the original at once, the copy swaps in at an invisible point; if the source has no hardware decode here (AV1 on the RX 5700) the still stays until the copy is ready (`video_wait_for_copy`). Stills/palette always come from the original. Speed modes Background (default, SCHED_IDLE) / Balanced / Fast; switching signals the runner (SIGUSR1) and re-prioritises live. Cancelling on slider release kills only the stale job's ffmpeg/RIFE process groups.
  - **Baked wind-down and replay bursts:** a baked file = first play + a chain of short **bursts** (ease-in 0 -> 1 then cosine wind-down, >= 1 s each; sidecar `<bake>.json`), RIFE v4.14 (`rife-ncnn-vulkan` from the AUR, models in `/usr/share/rife-ncnn-vulkan`; fallback ffmpeg `minterpolate`) synthesising in-between frames at F fps (60, or 120 only for >= 119 fps sources on a whole-multiple refresh). Every workspace switch (except special workspaces) plays the next burst and holds (`scripts/video-replay.lua` -> `mpv/replay.py <connector>` -> mpv IPC `winddown-restart`; ignored while a burst plays); station survives a player restart (`<runtime>/theme-video/<conn>.station`); the launcher also replays when the focused workspace is empty. Loops wrap around (K bursts per loop, capped by `burst_kmax`), non-loop clips restart from burst 0 with a fade segment when the cut is not clean. RIFE runs as a few long-lived directory-mode processes (workers sized by free VRAM, OOM halves them; arbitrary steps via the hard-linked slot trick; nearest source frame where the output steps >= 1 source frame). Bakes ignore load (user never changes wallpapers while gaming); `THEME_BAKE=0` disables. Colour: the PNG round trip must use the source's matrix/tags (`RGB_UP`, `bake_rgb_down`) or luma shifts; every concat part uses `-video_track_timescale 90000`; `BAKE_VERSION`/`OPT_VERSION` are in the cache keys. Do not compare `psnr` across files of different frame counts.
  - **Caveats:** baking cost grows with burst count; a failed/pending encode leaves the original running; monitor disconnect can segfault mpvpaper (stale pid file reaped by the next sync); unreadable videos show an "unreadable" cell and `apply` exits 1; changing a monitor's refresh later needs `theme.py video restart`; untagged videos can get a different matrix in the still. Not verified: the RX 5700 path, nvenc/qsv, real pointer drags on the Settings sliders.
  - Try it live: `python3 ~/.config/theme/theme.py render`, Settings > Wallpaper & theme, `theme.py video status`, `hyprctl layers -j` (mpvpaper must be in layer level 1).

### Shared building blocks (use these, do not hand-roll)

`Icon` (FA glyph Label; bar chips use `BarIcon`), `PanelHeader`, `ListRow` + `RowText` + `RowState` (list cards; fixed-width state column: check, pulsing ellipsis, plug on hover), `Notice` (confirmation / error / empty / setup steps), `LevelRow` (icon + `Slider` + value), `Meter`, `Segmented` (`fillWidth`: fill a width, equal buttons unless a label needs more), `SettingRow`, `Btn`, `Toggle` (only on main-section headers; item rows use `RowState`), `ModalMenu` + `KeyBadge` (keybind-opened layer modal, used by `Launcher`; `fixedScreen`, `respectReserved`, `focusItem`, `animated`), `PopupRegistration` (registers click-away things with `Popups`), `HoverGlow`, `SwipeDismiss`, `Icons.volumeGlyph`. Recipes: new popup = file with `PanelHeader` + sections, name in `PopupHost`'s content switch and width map, chip calls `bar.pop`, qmldir entry; new list row = `ListRow` + `RowText` + `RowState`/`Btn`; click-away non-popup = `PopupRegistration`.
- **HoverGlow:** pointer-following radial light, fill colour = the parent's current fill (opaque), strength by luminance, reach = max(3 x height, 0.7 x width); pointer tracking is a passive `HoverHandler` re-parented to the item (a child control's hover would otherwise drop `containsMouse`). `glow.hovered` is also what flat hover tints use. Built into ListRow/Tile/Btn/Toggle/Segmented, pickers, HA tiles, CalPanel cells, NotifCard buttons, Settings sidebar/cards/chips. Not on Sliders (user decision) or text links.
- **Slider:** square handle with a radius clamped by `Theme.radius`; pointer x maps through the handle's own travel so the pointer stays on the handle centre; Meter fill ends at the handle centre; after release a stepped value glides to its snapped position. `wheel: false` on every Slider inside scrolling Settings pages (a wheel over a timing slider once triggered a full theme apply). While pressed it grows into an in-app **glass lens** (`shaders/sliderlens.frag` + committed `.qsb`; build `/usr/lib/qt6/bin/qsb --qt6 -o sliderlens.frag.qsb sliderlens.frag` in `shaders/`; Qt caches a ShaderEffect shader per URL for the process life, restart after changing it): a `ShaderEffect` re-parented to the host card's parent, fed by a child `ShaderEffectSource` (must be a visual child, a parentless source segfaulted on window hide) that hides and redraws the card; optics are a port of the fork's `solidglassfinish.frag` driven by `GlassTuneCtl.values` (fork) or `defaults()` (stock); no lens on the software scene graph or a shader error (the handle just scales).
- **Qt/QML gotchas:** files with delegates / nested `Component`s start with `pragma ComponentBehavior: Bound` (before the imports) and every delegate declares `required property` for `modelData` / `index` / roles; `||` is for string / object fallbacks only, use `??` where `0` / `false` is a valid value; `Process` commands take argv arrays, never user data spliced into `sh -c` (positional args: `sh -c '... "$@"' sh arg...`); pollers bind `running` to visibility (`BarWidgets.shown(id)`, `panelOpen`); no `console.log` of notification content or the HA host; never use endless shell loops in a `Process` (they orphan to systemd on restart): poll with `Timer` + `FileView.reload()` (works on /proc) or one-shot Processes; no inline `component X:` in a file the running shell already loaded without one (hot reload fails "X is not a type"); hot reload is triggered by watched `.qml` files only (not `qmldir`) and a multi-file write (checkout, stash pop) can reload between files: a stale `qmldir` / new file then gives "X is not a type" until the next edit of any loaded file; a `Binding` whose `target` lacks the property warns even when `when` is false (assign from a function or Connections after an `in` check); never bind an item's own `visible` to its `visibleChildren` (latches off); a property named like an id shadows it; `clip: true` clips to the bounding box, not the rounded shape (use a MultiEffect mask for media art / thumbnails when radius > 0); `layer.effect` shader masks are not clipped by hot reload; singletons are not warmed in isolated instances; `Chip`'s hover MouseArea sits at `z: -1` so child MouseAreas get clicks; Binding-loop-prone `x` reading laid-out values goes into a delayed `Binding` (Chip row x); a `Behavior` easing must never be a binding that flips on close (use explicit open/close animations); a QML function named `closed` clashes with the window signal.

### Bar chip and icon alignment

- Tokens in `Theme.qml`: `chipHeight` (= barHeight - 2*barPad), `chipPadX`, `chipGap`, `chipIcon`. `Chip.qml`: content <= one icon box wide gives a 28x28 square; otherwise `ceil(content) + 2*padX`, row at a whole-pixel x; `implicitWidth = max(chipHeight, content + 2*padX)`. **Never set `implicitWidth` on a chip, never use `BarLabel` with the icon font.** Add a chip: `Chip { BarIcon { text; color } BarLabel { ... } }`.
- `BarIcon` is a fixed-size box with the glyph's *rasterised* ink centred (`InkMeter`: a Canvas that draws the string with the same font and scans alpha; x exact and not snapped, vertical baseline on a whole DEVICE pixel). `InkMeter.dpr` = `QsWindow.window.devicePixelRatio` (fractional; `getImageData` returns raw device pixels, which broke every scale != 1 until fixed). `Chip` centres the row on the visible ink of its first/last item. Don't read child `x`/`width` inside those bindings (binding loop). Vertical residual stays under about a pixel (whole-pixel baseline; a fractional baseline smears horizontal bars). Tray bitmaps keep their own padding. 1.5 is not a valid scale on 2560x1440 (Hyprland snaps to 1.6). No `QT_SCALE_FACTOR*` is set.

### Appearance (radius, gaps, floating bar)

Settings > Appearance changes corner radius, gaps, border and smart gaps (globally and per monitor), in Hyprland AND Quickshell, live.
- **Data:** `${XDG_STATE_HOME:-~/.local/state}/quickshell/appearance.json`, keys `version`, `radius`, `gap`, `edgeGap`, `border`, `barFloating`, `smartGaps`, `smartMonitors` (`{"<monitor key>": bool}`). Missing key = theme default; `{}`/no file = all defaults. Numeric keys are clamped (QML writer and Lua reader alike; limits in `Appearance.qml` / `managed.lua`; unset edgeGap = gap); `smartMonitors` is size- and key-limited, any invalid entry voids the whole map; the file has a size cap; non-objects/FIFOs/directories fall back to defaults. Precedence: Quickshell `appearance.json` > `theme.toml [settings]` > fallbacks; Hyprland `appearance.json` > hand-written config. `gaps_in = round(gap/2)`, `gaps_out = edgeGap ?? gap`. Monitor key = description as Hyprland reports it (connector as fallback, same rule `Appearance.monitorKey()` / `M.monitor_key()`); identical monitors without serial share a key.
- **Writers/readers:** only `Appearance.qml` writes (debounced, then `hyprctl eval "if layout_apply then layout_apply() end"`; `hyprctl reload config-only` instead when `smartGaps`/`smartMonitors` changed; hand edits are picked up by a FileView watch). The shell makes no hyprctl call at start. `theme.py` never touches the file. Hyprland reads it at every config load.
- **`hypr/hyprland/managed.lua`** holds everything Appearance does in Hyprland (never put hand-written settings there): loaded by `pcall(require, "hyprland.managed")` after `permissions`, before the scripts (`pip-reserve` requires it again; the module sets `package.loaded` first). It applies only the keys that are set (`hl.config` each in `pcall`), remembers a baseline read with `hl.get_config` and restores it on reset, and registers the smart-gaps rules (all registered once, flipped with `set_enabled`): a catch-all set (`w[tv1]`/`f[1]` workspace rules + no-border/no-rounding window rules) and one set per connected monitor (`m[desc:<description>]...`, falling back to `m[<connector>]` when `desc:` would not select exactly that monitor: prefix matches, identical descriptions, brackets/edge spaces), capped number of sets; hot-plug via `hl.on("monitor.added"|"monitor.removed"|"hyprland.start")`; subscriptions are kept in globals and removed at the next load so a reload does not stack them. Global `layout_apply()` never raises. A Lua error at config load disables the rest of the config, so everything is `pcall`ed and clamped. Reload pitfalls: Hyprland auto-reloads on save, so every file must load alone; managed.lua must stay after the hand-written modules. Same file also does animations (`anim_apply()`) and `apply_glass_layer_alpha()`.
- **Theme.qml API:** mirrors `radius` (R), `gap`, `gapIn`, `gapOut`, `borderSize`, `barFloating`, `smartGaps`; bar `barGap` (floating ? gapOut : 0), `barRadius`, `barPad`, `barReserve` (= barHeight + barGap); popups `popupGap` and `edgeGap` (both differ floating vs docked) — **`Theme.edgeGap` is NOT the user's `edgeGap` key (that is `Theme.gapOut`)**; concentric rule `inner(outer, inset)` and named radii `radiusChip`, `radiusItem`, `radiusPage`, `radiusDeep`, `radiusModal` (definitions in `Theme.qml`). Pills (toggles, tracks, dots) keep `min(h/2, ...)`. `Btn` takes `outerRadius` / `inset` and clamps to `floor(height/3)`; buttons not directly in a popup card set both (see the Settings close/page buttons, monitor-card buttons and chip eye buttons for examples). Accent stripes run from `y = radius` to `height - radius`.
- **Docked vs floating:** docked = margins 0, radius 0, reserve = barHeight (the committed look); floating = bar `gapOut` from the edges with radius R and reserve barHeight + gapOut. **Compact on fullscreen:** the `Bar.qml` window is always full width and `barHeight + Theme.barGap` tall (input `mask` = the visible `frame` item, so the transparent gap takes no clicks); `frame` is inset by `gapNow = barGap * (1 - compactState)` with radius `barRadius * (1 - compactState)`. `compactState` animates 0..1 (`popupMoveMs`, `popupEaseClose`, so Settings > Animations applies) while the monitor's active workspace has `hasfullscreen` (quickshell 0.3 has no such property: read from `lastIpcObject.hasfullscreen`, refreshed by a short timer after `fullscreen`/workspace/window raw events). BarReserve is untouched, so tiled windows do not reflow. A real fullscreen (mode 0) covers the Top layer, so the compact look only shows with maximize-style fullscreen (mode 1); the glass region is the `frame` background, so it follows the animation. Chip centres for popups are window coordinates (`centerOf`). Popup inset follows the bar's current frame: each Bar publishes `gapNow` via `Popups.setBarGap`, `PopupHost.inset = barHeight + Popups.barGapOf(screen) + popupGap` (identical to the old `barReserve` form when not compact; floating screenshots pixel-identical). Verified nested on fork and stock with two outputs; blur over a non-flat backdrop not checked. Toasts top = `edgeGap + barReserve` with a top bar, OSD bottom = fixed offset + `barReserve` with a bottom bar, TrayMenu `popupGap` from a floating bar.
- **Docked vs floating is per bar** (Settings > Bar > Style > Bar mode, `bars.json` key `floating`; linked monitors share it; not on the Appearance page any more): `BarConfig.floating/barGapOf/radiusOf/popupGapOf/edgeGapOf/reserveOf(screen)` are what Bar, BarReserve, PopupHost, Toasts and TrayMenu use. A bar without the key falls back to the global default (`Theme.barFloating`: appearance.json `barFloating` if present, else theme.toml `bar_floating`); no UI writes that key any more. Lua: `managed.bar_floating(mon)` / `bar_reserve(mon)` read the same bars.json key, used by `apply_bar_gaps` and `pip-reserve.lua`; `side-pin.lua` / `pip-orientation.lua` do not read the bar. The Appearance previews show the first bar's mode.
- **Respect reserved area** (Settings > Bar > Style > Reserved area, per bar, `bars.json` key `respectReserved`, default false = today: the bar ignores the monitor's `reserved_area` and other zones, `exclusiveZone -1`, at the screen edge). Compositor behaviour found nested: zone-0 surfaces are laid out AFTER all exclusive zones, and a zone>0 surface sits at the usable edge (inside `reserved_area`). So with the option the BAR is the exclusive surface (`exclusiveZone = reserveOf`, bar width shrinks by left/right reserved margins, `BarReserve` hides via `visible`, no double count), and PopupHost / Toasts / Osd use zone 0: their windows start right behind the bar, so their usual offsets subtract what the bar consumed (`BarConfig.zoneOf`, `insetOf`; PopupHost inset and bar-strip cut-out, Toasts/Osd insets). Toasts/Osd hop between screens: their zone is set 80 ms after a screen/option change (same-tick change was not applied to the re-created surface). Flush mode, floating gap, compact animation are unchanged; the Lua gap logic needs no change (windows start at the usable edge plus the bar's reserve). `pip-reserve.lua` `bottom_offset` is 0 for such a bottom bar (the bar sits above the reserved strip, where the video box lives). Live: the compositor re-lays the layers when `reserved_area` changes (measured: bar resized/moved). Verified nested fork + stock, top and bottom, flush + option, two monitors with different toggles, restart. Not covered: other clients' exclusive zones on the same edge (should follow, untested) and the BarReserve-less pinned-video strip on a real display.
- **Transparent when flush** (Settings > Bar > Backdrop, per bar, `bars.json` keys `transparentFlush` and `flushPadding` ("auto" or a total padding; range in `BarConfig.qml`)). `Bar.backdropOpacity` fades the bar background with the floating gap and `Glass.hidden` then declares no blur region, so a docked or compacted bar shows only its chips. **Flush mode = option on AND bar docked** (`BarConfig.flushMode`): Hyprland's outer gap on the bar's own side is 0 on that monitor (`managed.lua` `apply_bar_gaps`, per-monitor workspace rules replaced in place at every `layout_apply()`), and the bar height is chip height + padding (manual, or Auto = a multiple of the visible window gap, clamped; see `BarConfig.heightOf/padSide/reserveOf`, mirrored by `managed.bar_height` for `pip-reserve.lua`). Bar, BarReserve, PopupHost, Toasts and Osd use the per-screen functions; outside flush mode the bar is the plain `Theme` height. `BarConfig`'s save notifier calls `layout_apply()`. Caveat: with smart gaps off and a lone window, toggling may show the old gap until the next layout pass.

### Popups, motion and animations

- **Popup motion** (`PopupHost.qml`, tokens in `Theme.qml`): open = fade + scale + slide with a base duration; close = a shorter, decelerating variant; chip switch glides card x/width/height with the open curve and cross-fades content. `t` is driven by explicit `openAnim`/`closeAnim` NumberAnimations (not a Behavior), `visible: active || t > 0 || closeAnim.running`, `finishClose()` drops the content. Content is a Loader at the target size inside an Item sized to the animating card; Behaviors only run while `morphing`. Hyprland's layer fade for `qs-popup` is off (`no_anim` rule), so only QML animates; `layer.enabled` only during open/close. **Esc closes a popup via a Hyprland bind** (`Escape`, non-consuming, runs `qs ipc call popup esc` only while a `qs-popup` or `qs-toast` layer is mapped; the notification center lives in the `qs-toast` window); never use `keyboardFocus: Exclusive` on PopupHost (breaks click-away and one-click chip switching). `keyboardFocus` is `None` at map and `OnDemand` after a short `armed` timer (otherwise Hyprland sent `wl_pointer.leave` to the bar and the second click on the same chip at rest was lost). The PopupHost input mask cuts the bar strip out of the scrim's input region (`barStrip` subtracted) so clicking another chip switches popups in one click.
- **Glass during motion:** the card's glass region is the card itself (`Glass.qml` maps it through its transforms each frame). On the fork build with `layer_alpha_ref` the glass fades with the card (per-pixel by the surface alpha); on stock/older builds the glass cannot fade (solid_glass alpha = blurA x overallA, Quickshell has no `wp_alpha_modifier`), so `Theme.glassFades` is false and `Theme.glassScaleAt(t)` shrinks the glass region about the card centre below `glassTailFrom` to nothing (Glass.qml drops near-transparent regions). The OSD window follows; the toast / notification window is full screen and never resized, so no stale buffer can be stretched (cards also shrink their own glass through `NotifCard.glassScale`).
- **Animations settings** (`Motion.qml`, `SettingsAnimations.qml`, `hypr/hyprland/animations.lua`, managed.lua animations part): keys in `animations.json` (`QS_ANIM_FILE`; IPC `qs ipc call anim get | set <key> <value> | unset <key> | reset popup|hypr|all`; key names, ranges and allowed curve/style values are in `Motion.qml`): popup speed/curve/style, `launcherMotion`, global Hyprland enable/speed/curve, and per animation group Enabled/Speed/Curve. Hand-written curves/leaves live in `animations.lua` (edit them THERE); `A.BASE_MS` there and `Motion.baseMs` MUST be equal (Hyprland speed is in ds). Live apply: Motion runs `hyprctl eval "if anim_apply then anim_apply() end"`, which rewrites EVERY leaf from animations.lua (an unset key restores the hand-written value). Speed sliders share `Motion.speedRange` = `M.ANIM_SPEED` and a log mapping with a 1x tick. **Springs:** a spring curve must be referenced as `hl.animation{ spring = "<name>" }` (`bezier =` logs `no such bezier` without raising); springs ignore `speed`, so the factor is baked into per-factor curves `qs_spring_<f*100>` (stiffness f^2, dampening f). Workspace animations accept only slide/fade styles (specialWorkspace = fade). Disabling `fade` also disables inherited fade leaves.
- **Qt animation clock:** Quickshell is started with `QSG_USE_SIMPLE_ANIMATION_DRIVER=1` (`autostart.lua`): Qt's vsync-driven default ran animations too fast on the high-refresh monitor with several screens; the simple driver is correct and keeps the native frame rate. A hand-restarted shell needs the same env.
- **Slider glass, toasts, swipe:** `SwipeDismiss` (DragHandler on the card, a distance or flick threshold dismisses, spring-back/fly-off use the popup tokens; offset is a `Translate`, so `NotifSlot`'s own `x` animation and Glass.qml's transform collection keep working; toast timeout pauses while swiping; `NotifCard.dismiss()` is the single dismiss path (signal `dismissRequested`, `NotifSlot` animates out); every row owns its gap so it collapses with the row). Nested output at scale 0.5 mis-scales every glass blur region (compositor, not a shell bug).

Shared files stay identical on both machines; machine-specific edits go in their own file so merges stay clean.
- **kitty**: `config/kitty/kitty.conf` is shared (generic `font_family family="Paper Mono"`); `include ${KITTY_OS}.conf` pulls `linux.conf` or `macos.conf` (option-as-alt, title bar, brew variable-font spec, `clear_all_shortcuts` plus a minimal re-map: no kitty tabs/windows/layout keys, zellij does all of it; whether quit still works via the app menu is unverified). `host.py` (geninclude) is for per-hostname overrides. If kitty's font kitten appends a `BEGIN_KITTY_FONTS` block to `kitty.conf`, move it into the OS file. `kitty.conf.bak` was a stale kitty backup, removed.
- **zsh**: `.zshrc` branches on `$OSTYPE`/file existence (brew, plugin dirs, Android SDK, `update()`); `$HOME` instead of absolute paths. Put machine-local lines (installer-appended PATH/completion snippets, per-host aliases) in git-ignored `~/.zshrc.local`, sourced just before zoxide.
- **Linux-only** (not linked on mac, `install.sh` never runs there): hypr, quickshell, theme engine runs, hyprpaper outputs, launcher. **mac-only**: `config/aerospace`, `config/karabiner` (`karabiner.json` generated by `generate.py`). `config/theme/out/` is git-ignored and generated on Linux only; the Mac gets the committed default through `bin/theme-seed` (do not run the theme engine on the Mac), the Linux selection lives in the git-ignored `theme.local.toml`.
